# 인플루언서 브랜드 · 사전예약 제조 — 설계 (2단계)

> 작성 2026-10-13 · 대표 결정 "그렇게 한번 가보자" · 상태: **설계 초안 — 공장 입력값(§9) 대기**
> 선행: 1단계 = 지금 구조로 2026-10-14 라이브(바인허브·글로헬스 = 셀러리가 만든 첫 브랜드) · 2단계 = 이 문서(4~6주)

## 0. 한 줄

셀러리는 **인플루언서 브랜드를 만들어 파는 플랫폼**이 된다. 인플루언서가 제조를 의뢰하면 셀러리 식품 공장이 반맞춤(베이스 제품 + 라벨·이름)으로 만들고,
재고 부담 없이 **사전예약 라운드**로 먼저 판 뒤 최소수량을 넘기면 제조·배송하고, 못 넘기면 자동 취소한다. 셀러리가 제조·판매자, 인플루언서는 **브랜드 로열티**를 받는다.

## 1. 역할 · 법적 주체 (결정)

| 역할 | 누가 | 근거 |
|---|---|---|
| 제조업자 · 판매자(통신판매) · 표시·광고 책임 | **셀러리(위글로우)** | 건강기능식품은 브랜드 판매자도 유통전문판매업 신고·사업자가 필요 → 인플루언서 개인에게 요구하면 진입 장벽. 셀러리가 주체가 되면 제품 책임·광고 자율심의도 셀러리가 진다(통제력 = 리스크) |
| 브랜드 소유 표시 · 얼굴 · 판매 | **인플루언서** | 브랜드명·디자인 사용 허락 + 판매 활동 → **로열티**(확정 매출 × 요율). 사업소득 원천징수 3.3% 또는 세금계산서(지금 정산 정보 그대로) |
| 외부 파트너 브랜드(바인허브 등) | 기존 트랙 유지 | "파트너 브랜드" 로 남긴다. 1단계 라이브는 이 트랙 |

법 체크리스트: 품목제조신고(베이스 제품은 이미 신고된 것만) · 건기식 광고 자율심의(브랜드별 광고물) · 전자상거래법 선판매 후제조(배송 예정일·미달 시 취소 조건을 **예약 페이지에 명시**) · 표시광고법 인플루언서 광고 표기.

## 2. 핵심 흐름

```
① 제조 의뢰   인플루언서 콘솔 [내 브랜드 만들기] → 브랜드명·컨셉 → 베이스 제품 선택(§9 카탈로그) → 라벨·이름·패키지 문구
② 견적       셀러리 운영팀이 최소수량(MOQ) · 공급 원가 · 권장 판매가 · 로열티율 · 제조 리드타임 제시 → 인플루언서 수락
③ 예약 라운드 캠페인(round) 오픈: 목표 수량 · 마감일 · 배송 예정일 · 판매가 → 고객 사전예약 결제
④ 마감       목표 달성 → SUCCESS(제조 발주 · 배송 예정일 확정) / 미달 → FAILED(전건 자동 취소 · 환불 · 고객·인플 알림)
⑤ 제조·배송  공장 생산 → 송장 등록(지금 0049 추적 그대로) → 배송 완료
⑥ 정산       배송 완료 + 환불 보호 기간(D+21) 뒤 로열티 지급(지금 정산 파이프라인) · 재주문 라운드 또는 상시 판매 전환
```

이후 라운드: 1라운드 성공 상품은 **2라운드부터 재고를 두고 상시 판매**(지금 LIVE 캠페인 그대로)로 넘길 수 있다.

## 3. 데이터 모델 (0055~ · 기존 테이블 재사용 우선)

| 테이블 | 변경 | 메모 |
|---|---|---|
| `brands` | `kind text check in ('partner','influencer','sellery')` 추가 · `owner_seller_id uuid` (인플루언서 브랜드면 소유 인플루언서) | 인플루언서 브랜드도 `brands` 행 — 상품·캠페인·주문·CS·정산 전부 그대로 탄다. 로그인 주체는 셀러리 운영(관리자) |
| `base_products` **신규** | id · name · category · 품목제조신고 번호 · unit_cost · moq · lead_days · spec(용량·성분 jsonb) · active | 공장 카탈로그(§9). 관리자만 쓴다 |
| `brand_requests` **신규** | seller_id · brand_name · concept · base_product_id · label_text · status(`draft→submitted→quoted→accepted→product_created / declined`) · quote jsonb(moq·unit_cost·sale_price·royalty_rate·lead_days) · 운영 메모 | 제조 의뢰 1건. 수락되면 `brands`(kind=influencer) + `products` 생성 |
| `products` | `base_product_id uuid null` · `royalty_rate numeric null` | 인플루언서 브랜드 상품. `commission_rate` 자리를 로열티율이 대신한다(정산 식은 같다) |
| `campaigns` | `round_kind text check in ('normal','preorder')` · `goal_qty int` · `goal_amount bigint` · `close_at timestamptz` · `ship_eta date` · `funding_status text check in ('open','success','failed') null` | 예약 라운드 = 캠페인. `status` 는 그대로(LIVE=예약 접수 중) + funding_status 로 결과 |
| `orders` | `preorder boolean default false` | 예약 주문. 미달 취소 시 `CANCELED` + 환불(0008 취소 흐름 재사용) |
| `platform_settings` | `preorder_default_days`(라운드 기간 기본 10) · `royalty_default_rate`(0.35) | |

**상태 머신(예약 라운드)**: `SCHEDULE_CONFIRMED`(오픈 예정) → `LIVE`(접수 중, funding_status=open) → 마감 틱 → `success` 면 `CLEARING` 로 가지 않고 **`PRODUCING`(신규 상태)** → 송장 등록 → `SHIPPED`(신규) → 배송 완료 D+21 → `CLEARING` → `SETTLED` / `failed` 면 **`FUNDING_FAILED`(신규 종료 상태)** + 전건 취소. 지금 `app_campaign_tick`(0018)에 "close_at 도래 → 달성 판정" 분기를 추가한다.

## 4. 결제 (사전예약)

| 안 | 방식 | 장단 |
|---|---|---|
| **A (v1 채택)** | 지금처럼 **즉시 승인**, 미달 시 마감 틱이 `tossCancel` 전액 취소 | 코드 변경 최소(0008 취소 재사용). 토스 전액 취소 시 수수료 환급 조건 확인 필요(§9). 고객에게 "미달 시 자동 환불" 명시 |
| B | 빌링키 등록 후 마감 시 일괄 결제 | 고객 체감 최선(돈이 안 빠짐). 토스 자동결제 계약·빌링키 저장 필요 → v2 |
| C | 가상계좌 예약(입금 대기) | 전환율 낮음 · 미입금 관리 부담 → 보류 |

체크아웃 변경: 예약 라운드 상품이면 결제 화면에 **배송 예정일 · 마감일 · 미달 시 자동 환불** 고지 블록 + 동의 체크(전자상거래법). 재고 차감 대신 `goal_qty` 진행률 갱신.

## 5. 정산 (로열티)

식은 지금 0053 과 같다 — `commission_rate` 자리에 `royalty_rate`. 브랜드 몫은 셀러리(제조·판매자)이므로 **브랜드 지급 행이 없고** 셀러리 손익에 원가가 들어간다:

```
net          = 확정 매출(배송 완료 · 환불 제외)
royalty      = base × royalty_rate            → 인플루언서 지급(− 원천징수 − 플랫폼 이용 3%? → §9 결정: 로열티에는 이용 수수료를 받지 않는 게 자연스럽다)
cogs         = qty × base_product.unit_cost  → 셀러리 원가(관리자 손익에만)
sellery_net  = net − royalty − cogs − pg(1.9%) − vat
```

관리자 손익 화면(`app_admin_revenue`)에 `cogs` 열 추가 · 브랜드 지급 행은 `brands.kind='influencer'` 면 생성하지 않는다(`app_admin_settle_run` 분기).

## 6. 화면

- **인플루언서 콘솔**: `내 브랜드`(없으면 [브랜드 만들기] 위저드 = 제조 의뢰 §2①) · 의뢰 상태 카드(견적 수락/거절) · 내 상품 · 예약 라운드 열기(목표 수량·마감일 — 셀러리가 MOQ 이상으로 제한) · 라운드 진행률 · 정산(로열티). 기존 "상품 갤러리"는 파트너 브랜드 트랙으로 남긴다.
- **관리자 콘솔(제조 관리)**: 베이스 제품 카탈로그 CRUD · 제조 의뢰 큐(견적 작성 → 발송 → 수락 시 브랜드·상품 자동 생성) · 라운드 모니터(진행률 · 마감 예정 · 달성/미달 처리 결과) · 생산 발주서(달성 라운드 수량 집계 CSV) · 송장 등록(지금 브랜드 콘솔의 주문 화면을 관리자로 옮긴 것).
- **고객(shop)**: 예약 페이지 = 지금 `/s/<handle>/<code>` 에 **진행률 바 · 목표 수량 · 마감 D-day · 배송 예정일 · "미달 시 전액 자동 환불" 배지**. 홈 카드에 "예약 접수 중" 톤. 주문 상세에 라운드 결과 상태.
- **브랜드 콘솔(기존)**: 파트너 브랜드 전용으로 유지. 인플루언서 브랜드의 주문·CS·송장은 관리자가 처리.

## 8. 리스크 · 대응

- **품질 집중**: 공장 하나 = 사고 한 번이 전 브랜드로. 베이스 제품을 소수(10~20종)로 시작, 검증된 품목만.
- **리드타임**: 완전 맞춤은 6~8주 → 반맞춤(라벨·이름)으로 2~3주. 마감일 + lead_days = 배송 예정일을 페이지에 그대로 쓴다.
- **미달 환불 비용**: A안은 토스 수수료 환급 조건에 달렸다(§9). 불리하면 B안 우선.
- **인플루언서 기대치**: 로열티는 "남의 상품 공구 30%" 와 비교되는 숫자다(2026-10-12 시세 조사: 일반 10~30% · 메가 40~50%). 기본 35%, 상위 등급 40%+ 가 설득력 있다 — 원가율이 낮은 건기식·이너뷰티라 가능.

## 9. 대표 · 공장에서 받아야 할 입력 (이게 와야 PR-A 착수)

1. **베이스 제품 카탈로그**: 품목명 · 품목제조신고 번호 · 용량/포장 단위 · 공급 원가(단위당) · MOQ · 리드타임(일) · 권장 판매가. 처음 10~20종.
2. **로열티율 기본값** 과 등급별 차등 여부(예: 기본 35% · 플래티넘↑ 40%).
3. **예약 라운드 기본 기간**(마감까지 며칠) 과 **목표 기준**(수량 MOQ 그대로인지, 금액 하한인지).
4. **토스 전액 취소 수수료 환급 조건** 확인(결제 당월/익월) → A안 확정 여부.
5. 인플루언서 브랜드의 **광고 자율심의 주체·비용** 과 라벨 디자인(템플릿 제공 vs 인플루언서 제작).
6. 로열티에 플랫폼 이용 수수료 3% 를 받을지(§5).
