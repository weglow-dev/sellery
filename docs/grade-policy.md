# 셀러리 등급 정책

> 최종 수정: 2026-09-14 · 근거: 코드 상수(js/00-core.js, js/02-state.js 등) + 브랜드/인플루언서 제안서(2026.09) · 상태: 프로토타입 기준(실서비스 전 확정 필요)

이 문서는 인플루언서 등급(7단계)과 브랜드 등급(7단계)이 **코드에서 실제로 어떻게 계산되고 어디에 쓰이는지**를 정리한다. 숫자와 규칙은 모두 코드 상수에서 가져왔고, 제안서와 다른 부분은 "제안서 표기", 제안서에는 있지만 코드에 없는 부분은 "미정(코드 미구현)"으로 표시했다. 관련 정책: [settlement-policy.md](./settlement-policy.md) · [period-policy.md](./period-policy.md) · [sample-policy.md](./sample-policy.md) · [points-policy.md](./points-policy.md)

## 1. 기본

| 항목 | 인플루언서 등급 | 브랜드 등급 |
|---|---|---|
| 단계 | 7단계 (스타터 → 블랙) — `GRADES` | 7단계 (스타터 → 블랙) — `BGRADES` |
| 기준값 | `m3Sales` — "최근 3개월 확정 매출" (₩) | `bGmv(b)` — 누적 확정 매출(GMV) (₩) |
| 판정 | `gradeOf(m)` = `GRADES`에서 `m >= min`인 첫 단계(위에서부터 탐색) | `bgradeOf(v)` 동일 방식 |
| 등급명 | `gname(s)` | `bgname(b)` |
| 강등 | `gradeOf`는 기준값이 내려가면 즉시 하위 등급을 반환하지만, `m3Sales`는 `ACT.runSettle`에서 **더해지기만** 하고 줄어드는 경로가 없어(3절 롤링 차감 미구현) **프로토타입에서는 강등이 일어나지 않는다** | 환불(`ACT.refund` — 주문 PAID → REFUNDED)로 `netOf(c)`가 줄면 GMV가 즉시 감소해 하위 등급, 별도 유예 없음(정산 완료 판매·샘플 구매 주문은 환불 불가) |
| 실제 효과 | 수수료 보너스 · 샘플 월 한도 · 무상 샘플 자격 · 독점권 신청 · 기간 우선권 · 데이터 열람 가격 · 제안권 가격 | 플랫폼 수수료 할인 · 레퍼런스 무료 열람(월 5회) |

등급 뱃지는 `gfull(등급명)`이 아이콘(`GICON`) + 등급명으로 그리며, 같은 아이콘 세트를 인플루언서·브랜드가 공유한다. 각 화면의 피라미드(`pyrHtml`)에 찍히는 "상위 N%"는 단계별 **고정 라벨**(`pct`)이고, 실제 분포에서 계산하지 않는다.

| 신상품 우선 제안권 (플래티넘) | 미정(코드 미구현) | 혜택 문구에만 존재 |

## 3. 기준값 — "최근 3개월 확정 매출" `m3Sales`

- **시드값은 고정**이다. 데모 인플루언서의 `m3Sales`는 `seedData()`에 하드코딩되어 있다(아래 표).
- **갱신 시점은 정산 실행(`ACT.runSettle`) 한 곳뿐**이다. 캠페인이 SETTLED로 바뀔 때 `sl.m3Sales += k.net`(확정 매출 = 결제 − 환불)을 더한다. 단 **시드 이후 생성된 캠페인(id 숫자 ≥ 100)만** 누적하고, 시드 캠페인(c1~c13)은 정산해도 더하지 않는다(시드 지표 중복 방지).
- 진행 중(LIVE) 매출은 등급에 반영되지 않는다 — 정산 완료 기준.
- "최근 3개월" 롤링 차감(3개월 지난 매출 제외)은 **미정(코드 미구현)** — 현재는 누적만 된다. 실서비스에서는 기준 기간·차감 방식 확정 필요.
- 같은 값이 셀러리(🥬) 획득 기준이기도 하다: `celEarned(seller) = floor(m3Sales / CELERY_PER)` (₩5,000,000당 1🥬) → [points-policy.md](./points-policy.md).
- **거절·패스는 등급에 영향이 없다.** 브랜드 제안 거절(`ACT.declineInvite` → DECLINED, 제안권 환급만 수행)·테스트 후 패스(`ACT.passCamp` → PASSED, 상태 전환만)·브랜드의 샘플 거절(`ACT.rejectSample` → REJECTED)은 `m3Sales`·등급·갤러리 노출·자동 제안 후보 어디에도 반영되지 않는다 — DECLINED/PASSED/REJECTED 건수를 읽는 곳이 코드에 없다(`vGallery` 필터는 등급·플랫폼만 검사). `autoMatches()`·브랜드 홈 맞춤 추천·상품 카드의 "진행 중" 판정은 REJECTED/PASSED/DECLINED/SETTLED를 **종료**로 보고 그 인플루언서를 다시 후보에 포함한다. 인플루언서 제안서 p.9 "거절해도 등급·노출에 영향이 없어요", p.11 "패스해도 … 등급·노출·다음 제안에 아무 영향이 없어요"와 일치(불이익 로직 부재로 충족). 단 상품당 무상 샘플 1회 판정 `hadFreeSample`은 REJECTED·DECLINED만 제외하고 PASSED는 제외하지 않으므로, 패스한 상품의 무상 샘플은 소진된 것으로 남는다 → [sample-policy.md](./sample-policy.md).

## 4. 상품 독점권 (`exclusive`)

- 브랜드가 상품 등록/수정 시 **독점권 오퍼**를 켤 수 있다. 선택지는 `GRADES.slice(0,4)` = **블랙 / 다이아 / 플래티넘 / 골드 "등급 이상"** 4가지 + "사용 안 함". 독점권 내용(`label`, 예: "인스타그램 판매 독점권 · 3개월")은 자유 입력이며 기본값은 "{등급} 등급 독점권".
- 기준 등급 `exGradeOf(p)` = `p.exclusive.grade`. (구형 데이터 호환: `grade`가 없으면 `min ≥ ₩50,000,000`이면 다이아, 아니면 플래티넘.)
- 신청 자격 `exEligible(p, s)`: 내 등급 순위가 기준 등급 순위 이상(`tierIdx` 비교). 상품 상세 모달에서 충족 시 "독점권 신청" 버튼, 미달 시 "등급 미달 — 내 등급 {g} / 필요 {exg} 이상"(비활성).
- 흐름: 인플루언서 신청(`reqExclusive` → `exclusiveReqs` PENDING, **신청 시 브랜드에 프로필 공개**) → 브랜드 요청함에서 승인(`approveExcl` → `p.exclusiveSellerId` 확정) 또는 거절(`rejectExcl`). 이미 신청(거절 아님)이 있으면 "신청 완료 — 브랜드 승인 대기".
- 확정 효과: 다른 인플루언서는 샘플 버튼이 "독점 잠김"이 되고 샘플 요청·브랜드 제안 수락이 막히며, 브랜드도 다른 인플루언서에게 제안할 수 없고, 자동 제안 후보에서 해당 상품이 빠진다. 확정 인플루언서는 상세 모달에 "독점 인플루언서 확정됨 — 나 🎉", 타인에게는 "(○○○ 인플루언서)".
- **확정 후 해제 불가**: 상품 수정(`ACT.saveProduct`)에서 독점권을 "사용 안 함"으로 바꿔도 `exclusiveSellerId`가 있는 상품은 `p.exclusive`를 지우지 않는다(`else if(!p.exclusiveSellerId) delete p.exclusive`). 확정된 독점권을 푸는 액션은 없다.
- 노출: 인플루언서 홈 "지금 셀러리에서"에 미확정 독점 오퍼 1건("{상품} 독점권 오퍼 오픈 — {등급} 등급 이상 신청 가능"). 브랜드 상품 관리(`vBrandProducts`)에는 "{등급} 이상" 뱃지 + "확정" 태그, 관리자 상품 표에는 등급 뱃지만("이상" 표기 없음) + "확정" 태그.
- 시드: p1 버닝온 = **다이아 이상** "인스타그램 판매 독점권 · 3개월", p4 GL-01 스킨 샷 = **플래티넘 이상** "이너뷰티 단독 판매권 · 2개월". 독점권 신청 시드 `exclusiveReqs` x1: **s4 서아(비공개·다이아) → p1 버닝온 PENDING**(어제 신청) — 초기 상태에서 b1 바인허브 요청함에 서아의 실명·핸들과 "비공개 프로필 (독점권 신청으로 공개)"가 표시되고 승인/거절 대기 중이다.

제안서 표기: 인플루언서 제안서 p.6 "다이아 이상 상품 독점권 신청 가능". 코드는 상품별 기준 등급(골드~블랙)을 브랜드가 정하며, 시드 상품 하나는 플래티넘 기준이다.

## 5. 브랜드 등급 7단계

`BGRADES` 배열 그대로. 기준은 **누적 확정 매출(GMV)** `bGmv(b)` = `gmvBase`(시드 과거 실적) + 해당 브랜드 상품의 모든 캠페인 `netOf(c)`(상태 PAID 주문의 단가×수량 합, 환불 제외). 인플루언서와 달리 **정산 전 LIVE 결제도 즉시 반영**되고, 인플루언서 샘플 구매 주문(`sample:true`)도 PAID이므로 포함된다.

| 등급 | 기준 (누적 GMV) | 상위 라벨 | 수수료 할인 `BG_DISC` | 혜택 문구 (`perk`) |
|---|---|---|---|---|
| 블랙 | ₩1,000,000,000 이상 | 상위 1% | −2%p (0.02) | 플랫폼 수수료 −2%p · 전담 파트너 매니저 · 기획전 최상단 |
| 다이아 | ₩500,000,000 이상 | 상위 3% | −1.5%p (0.015) | 수수료 −1.5%p · 스카우트 열람권 월 5회 무료 |
| 플래티넘 | ₩200,000,000 이상 | 상위 8% | −1%p (0.01) | 수수료 −1%p · 상위 인플루언서 우선 매칭 |
| 골드 | ₩80,000,000 이상 | 상위 18% | −0.5%p (0.005) | 수수료 −0.5%p · 카탈로그 상단 노출 |
| 실버 | ₩30,000,000 이상 | 상위 35% | 0 | 상품 검수 우선 처리 |
| 브론즈 | ₩10,000,000 이상 | 상위 60% | 0 | 인증 브랜드 뱃지 |
| 스타터 | ₩0 이상 | 상위 100% | 0 | 기본 조건 |

### 5.1 수수료 할인 적용 방식

- `bDiscOf(b) = BG_DISC[bgname(b)] || 0`. `calc()`에서 `bDisc = net × bDiscOf(b)`를 **브랜드 정산액에 더하고**(`brandPay = net − pg − sf − pfGross + bBoost + bDisc`) 플랫폼 수수료에서 뺀다(`pf = pfGross − costs`). 인플루언서 몫은 변하지 않는다.
- 정산 미리보기 행: "브랜드 {등급} 등급 수수료 할인 −N.N%p · +₩…". 브랜드 등급 카드 각주: "수수료 할인은 플랫폼 중개 수수료(10%)에서 차감 · 누적 확정 매출(GMV) 기준".
- 제안서 표기: 브랜드 제안서 p.5 "등급 할인 시 최대 −2%p", p.10 "브랜드 등급 할인(−0.5~2%p)은 상대 몫을 깎지 않고 셀러리가 부담" — 코드와 일치.

### 5.2 혜택 문구 중 구현 여부

| 문구 | 구현 | 근거 |
|---|---|---|
| 플랫폼 수수료 −N%p | 구현 | `BG_DISC`, `calc()` |
| 스카우트 열람권 월 5회 무료 (다이아) | 구현 — **블랙도 동일 적용** | `freeRefLeft(b)`: 등급이 다이아·블랙이면 `5 − 이달 사용 횟수`, 아니면 0 (6절). 블랙 혜택 문구에는 빠져 있으나 코드는 블랙에도 준다 |
| 전담 파트너 매니저 · 기획전 최상단 (블랙) | 미정(코드 미구현) | 문구만 |
| 상위 인플루언서 우선 매칭 (플래티넘) | 미정(코드 미구현) | `autoMatches()`는 브랜드 등급을 보지 않는다 |
| 카탈로그 상단 노출 (골드) | 미정(코드 미구현) | 상품 갤러리 정렬은 실사진 우선 → 부스트 패스(🥬) 순, 브랜드 등급 무관 |
| 상품 검수 우선 처리 (실버) | 미정(코드 미구현) | 검수 대기 정렬 규칙 없음 (우선 검수는 🥬 1 "우선 검수권"으로 별도 판매) |
| 인증 브랜드 뱃지 (브론즈) | 미정(코드 미구현) | 등급 기준 뱃지는 없다. 고객 인증 모달 "공급 브랜드" 행은 브랜드명 + 등급 뱃지 뒤에 사업자번호가 있으면 "· 사업자 {번호}", 없으면 "· 인증 브랜드" **대체 문구**를 붙일 뿐 — "인증 브랜드"는 사업자번호가 없는 브랜드에 나오는 문구이지 인증 뱃지가 아니며 등급과 무관 |

### 5.4 인플루언서·고객 화면의 브랜드 등급 노출

- 인플루언서 상품 갤러리 카드(`vExplore` 상품 카드)와 상품 상세 모달(`productDetailModal`) 헤더에 브랜드 칩 옆 **브랜드 등급 뱃지** `gfull(bgname(b))`를 표시한다. 인플루언서가 브랜드 등급을 보고 진행 여부를 판단하는 장치 — 인플루언서 제안서 p.7 "브랜드도 검증합니다 — 정산 이력이 있는 브랜드인지, 등급이 어떤지 확인하고 시작하실 수 있어요".
- "정산 이력"은 별도 표시가 없고, 상품 상세의 익명 판매 실적 표 상태 칩(정산 완료 등 — 7.2절)으로 간접 확인한다.
- 관리자 상품 표의 브랜드 열, 고객 판매 인증 모달 "공급 브랜드" 행에도 같은 뱃지가 붙는다.

## 6. 등급별 데이터 열람 가격 `DATA_PRICE` (🥬)

브랜드가 인플루언서 1명의 상세 지표(3개월 매출 · 판매당 평균 · 참여율 · 이력 · 외부 판매 예상)를 열 때 내는 셀러리. **열람 대상 인플루언서의 등급**이 높을수록 비싸다. `dataPrice(s) = DATA_PRICE[gname(s)] || 2`.

| 대상 등급 | 스타터 | 브론즈 | 실버 | 골드 | 플래티넘 | 다이아 | 블랙 |
|---|---|---|---|---|---|---|---|
| 가격 | 🥬 1 | 🥬 1 | 🥬 2 | 🥬 2 | 🥬 3 | 🥬 4 | 🥬 5 |

적용 지점(모두 `spendData(bid, s, memo)` 경유):

| 화면 | 액션 | 대상 |
|---|---|---|
| 인플루언서 갤러리 카드 · 프로필 모달 "🥬 N · 데이터 확인하기" | `unlockSellerData` | 공개 프로필 — 브랜드별 `brandDataUnlocks[bid]`에 기록 |
| 갤러리 "익명 인플루언서 스카우트" 카드 "🔓 레퍼런스 열람 · 🥬 N" | `unlockRef` | 비공개 프로필 — 전역 `unlockedRefs`에 기록(브랜드 구분 없음, 프로토타입 단순화) |
| 브랜드 홈 "지금 잘 파는 인플루언서 TOP5" 비공개 행 클릭 | `topSeller` → `unlockRefGo` | 비공개 프로필 — 열람 후 바로 제안 모달 |

무료가 되는 경우 — 코드 검사 순서대로:

**공개 프로필** (갤러리 카드 · 프로필 모달 = `sellerCard`, 액션 `unlockSellerData`)

1. 카드를 그릴 때 `unlocked = worked || passActive(bv,'datapass',30) || brandDataUnlocks[bv.id].includes(s.id)`를 먼저 판정한다. 하나라도 참이면 **열람 버튼 자체를 그리지 않고 무료**이며, 다이아·블랙 무료 횟수도 소모하지 않는다.
   - `worked` = 이 브랜드 상품으로 LIVE/CLEARING/SETTLED 이력이 있는 인플루언서 — 카드에 "함께 판매 · 데이터 무료" 태그.
   - 데이터 패스(30일, 🥬 30) 보유 중.
   - 이미 열람(`brandDataUnlocks[bid]`에 기록, 브랜드별).
2. 버튼을 눌러 `spendData`가 호출될 때 **브랜드 등급 다이아·블랙**이고 `freeRefLeft(b) > 0`이면 🥬 차감 없이 열람하고 `b.freeRefUsed[YYYY-MM]`을 +1. 월 5회, 달력 월(`ymd(today()).slice(0,7)`) 기준 리셋. 홈 "내 자산" 카드에 "무료 데이터 열람 N회 남음"(다이아·블랙) 또는 "다이아↑ 혜택"(그 외).
3. 아니면 🥬 `dataPrice(s)` 차감(`celSpend`).

**비공개 프로필** (갤러리 스카우트 카드 `unlockRef` · 홈 TOP5 `topSeller` → `unlockRefGo`)

1. 전역 `unlockedRefs`에 있으면 열람 상태(브랜드 구분 없음). **`worked`·데이터 패스는 검사하지 않는다** — 함께 판매한 적이 있어도, 데이터 패스가 있어도 비공개 인플루언서는 열람권을 쓴다(프로토타입 단순화).
2. 미열람이면 위 2·3과 동일: 다이아·블랙 무료 잔여 → 🥬 `dataPrice(s)`.

한 번 열면 재차감 없음. 셀러리 부족 시 "🥬 셀러리가 부족합니다 (보유 N / 필요 M) — 셀러리 샵에서 충전하세요" 토스트.

제안서 표기: 브랜드 제안서 p.6 "기본 정보는 무료, 판매 실적은 필요할 때만 엽니다. 함께 판매한 적 있는 분의 데이터는 계속 무료예요" — 코드에서 "함께 판매 무료"는 **공개 프로필 카드에만** 적용되고 비공개 프로필(스카우트·TOP5)에는 적용되지 않는다.

### 6.1 등급이 붙는 다른 셀러리 항목

- **다이아↑ 인플루언서 제안권 (🥬 10)**: 브랜드가 **다이아·블랙** 등급 인플루언서에게 판매 제안을 보낼 때 자동 차감(`confirmInvite`). 자동 제안(`runAutoPropose`)도 동일하게 차감하며 잔액이 10 미만이면 그 건은 보류. 인플루언서가 거절하면 전액 환급(`declineInvite` → `c.celRefunded`).
- 다른 등급에게 보내는 제안은 무료.
- 제안서 표기: 브랜드 제안서에는 다이아·블랙 제안권(🥬 10) 언급이 없고, 브랜드 부담은 p.2 "0원 · 입점비·구독료·보증금 없음", p.4 "없음 · 팔린 만큼만"으로 적혀 있다(🥬 비용은 p.6 "🥬 3 · 데이터 열람하고 제안하기"만 노출). 브랜드의 🥬는 누적 GMV ₩5,000,000당 1개 획득(`celEarned` — 브랜드는 `bGmv` 기준) 또는 충전(`TOPUP`: 5개 ₩100,000 / 10개 ₩190,000 / 30개 ₩540,000)이므로, 제안서만 읽은 브랜드에게는 예상 밖 비용이다 — 실서비스 전 제안서·정책 정합 필요.

## 7. 랭킹 · 익명 리더보드

### 7.1 인플루언서 센터 "랭킹·등급" (`vRank`)

- 헤더: "인플루언서 랭킹 — 최근 3개월 매출 기준 · 등급 보너스는 플랫폼 수수료에서 지급".
- 왼쪽 카드: 내 등급·3개월 매출·피라미드(`pyrHtml(GRADES)`)·다음 등급까지 진행 바(`m3Sales / next.min`)와 "다음 등급 {next}까지 ₩… 남음 — 달성 시 {perk}". 최고 등급이면 "최고 등급입니다 · {perk}".
- 오른쪽 카드: 7단계 전체 혜택 표(`GRADES` 그대로, 내 등급 굵게).
- **리더보드 — 매출 효율 랭킹**: 전체 인플루언서(비공개 포함)를 `m3Sales` 내림차순. 열: # · 인플루언서 · 카테고리 · 3개월 매출 · 매출/팔로워(`m3Sales/followers`) · 매출/좋아요(`m3Sales/likesAvg`) · 등급.
- **익명 규칙**: 나만 실명+핸들+"MY" 뱃지, **다른 인플루언서는 전원 "○○○ 인플루언서"**(공개 프로필이어도). 각주: "※ 타 인플루언서는 익명(○○○)으로만 노출됩니다 — 순위와 지표만 공개, 저격 불가."
- 인플루언서 홈의 "내 등급 — 상위 N%" 카드는 같은 정보의 축약판이며 클릭 시 이 화면으로 이동.

### 7.2 상품별 판매 실적 (상품 상세 모달)

"이 상품의 판매 실적 — 인플루언서 익명": 판매자 이름 없이 팔로워 · 좋아요 · 참여율 · 기간 · 확정 매출 · 상태만 표시. 첫 행만 무료, 나머지는 블러 — 인플루언서용 "매출 데이터 확인권"(🥬 2, 계정에 영구 적용) 구매 시 전체 열람.

제안서 표기: 인플루언서 제안서 p.7은 "상품마다 지난 판매 실적이 공개돼요. 판매당 평균과 최고 기록을 보고 … 확인한 뒤 결정"으로 **무료 공개처럼** 서술하지만, 코드는 첫 행만 무료이고 나머지는 🥬 2 확인권(`buyDataPass`, 계정 영구) 뒤에 잠근다(열 구성도 제안서의 판매당 평균·최고 기록·예상 수령액이 아니라 팔로워·좋아요·참여율·기간·확정 매출·상태). 제안서를 먼저 읽은 인플루언서가 잠긴 실적을 보고 혼란을 겪을 수 있으므로 실서비스 전 확정 필요 — 주 문서는 [points-policy.md](./points-policy.md).

### 7.3 비공개 프로필 (`hidden`)

- 관리자만 켜고 끌 수 있다(`admToggleHidden`). 시드에서는 s4 서아·s5 로라(둘 다 다이아).
- 브랜드 화면에서 "○○○ 인플루언서"로 가려지는 곳은 **네 군데뿐**이다: 홈 "지금 잘 파는 인플루언서 TOP5" · 홈 소식 "스카우트" 항목 · 갤러리 "익명 인플루언서 스카우트" 섹션 · 제안 모달(`inviteModal` 헤더 "○○○ 인플루언서 (익명)"과 발송 토스트). 여기서는 등급 뱃지·3개월 매출·카테고리는 공개, 팔로워·좋아요는 "●●●,●●●"로 가리고, 레퍼런스 열람(6절) 후 팔로워·참여율·매출/팔로워가 열린다.
- **신원 공개 시점**: 브랜드 제안을 수락할 때(`acceptInvite` — 스레드에 "🔓 익명 인플루언서 신원 공개 — {이름} {핸들}") 또는 독점권을 신청할 때(4절). 갤러리 안내문도 "제안이 수락되는 순간 DM이 열리고 신원이 공개됩니다"라고 적는다.
- **프로토타입 미차단**: 비공개 인플루언서가 스스로 샘플을 요청(`reqSample`)하거나 샘플을 구매(`confirmSampleBuy`)하면, 브랜드 요청함 행(`vRequests` — "{상품} · {아이콘} {이름} {핸들}")·캠페인 행(`campRow` 브랜드용 — "{이름} {핸들} · 팔로워 N")·스레드 시스템 메시지("인플루언서 {이름}({핸들})가 샘플을 요청/구매했습니다")·캠페인 상세 "샘플 요청 검토" 카드("{이름} {핸들} · 팔로워 N · 등급 …")에 **실명·핸들이 그대로 노출**된다 — 이 경로에는 `hidden` 분기가 없다. 브랜드 홈 "내 상품을 조회한 인플루언서"도 `hidden`을 거르지 않는다(시드 `productViews`에는 비공개 인플루언서가 없어 초기 화면에서는 드러나지 않음). 실서비스에서는 익명 유지 범위 확정 필요.
- 관리자 화면은 항상 실명 + "비공개" 태그.
- 고객 판매센터·인증 모달은 판매 인플루언서 실명 + 등급 뱃지를 표시한다.

### 7.4 브랜드·관리자 랭킹

- 브랜드 홈 "지금 잘 파는 인플루언서 TOP5": 전체 인플루언서 `m3Sales` 내림차순 5명, 비공개는 "○○○ 인플루언서", 클릭 시 제안(비공개는 열람 후 제안).
- 관리자 "인플루언서" 탭: 등급 칩 필터(`GRADES` 중 인원 있는 등급만) + `m3Sales` 내림차순. "브랜드" 탭: 등급 · 누적 GMV 표시. "매칭·자동 제안": 성장세(`growthOf`) 순 TOP6와 자동 제안 후보(`autoMatches`). 후보 = 자동 제안 ON 브랜드의 노출 중·독점 미확정 상품 × **카테고리 적합(`catFit`, `CATMAP` 그룹 일치) 인플루언서 중 그 상품에 진행 중 캠페인이 없는 사람**(REJECTED/PASSED/DECLINED/SETTLED는 종료로 봄), 점수 = `round(0.6 × 성장세 + 매출/팔로워 ÷ 10 + 공개 프로필 5)` — 카테고리 적합은 점수 항이 아니라 후보 필터다. 상품당 점수 상위 2명.

## 8. 갤러리 노출 순서 · 등급 필터

### 8.1 브랜드 → 인플루언서 갤러리 (`vGallery`)

| 구역 | 대상 | 순서 |
|---|---|---|
| 등급 필터 칩 | 전체 · 실버 이상 · 골드 이상 · 플래티넘 이상 · 다이아 이상 (+ 메인 SNS 필터) | `tierIdx(내등급) ≤ tierIdx(필터)` — 공개·스카우트 섹션 모두에 적용 |
| "{브랜드} 맞춤 추천 인플루언서" | 공개 프로필 2명 | 점수 = 카테고리 적합(`CATMAP`) +2 · 매출/팔로워 ÷300 · **프로필 상단 노출 패스(🥬 3, 7일)** +5 — 내림차순 |
| "전체 인플루언서" | 공개 프로필 전원(필터 적용) | 시드 순서 그대로(정렬 없음) |
| "익명 인플루언서 스카우트 — 유료 레퍼런스" | 비공개 프로필(필터 적용) | 시드 순서 그대로 |

브랜드 홈 "{브랜드} 맞춤 추천"(3명)은 별도 점수(카테고리 적합 +2 · 성장세 ÷50 · 매출/팔로워 ÷300, 진행 중 캠페인 있는 인플루언서 제외).

제안서 표기: 인플루언서 제안서 p.6 "브랜드 갤러리 상단 노출로 제안 증가"는 등급 혜택으로 적혀 있으나, 코드의 갤러리 순서에 **등급 자체는 반영되지 않는다**(매출 효율 지표가 간접 반영될 뿐). 미정(코드 미구현).

### 8.2 인플루언서 → 상품 갤러리 (`vExplore`)

- 상품 정렬: 실사진(누끼) 상품 우선 → 부스트 패스(브랜드 🥬 3, 7일) 상품 우선. 등급 무관.
- "{내 등급} 등급 이상 인플루언서 베스트셀링 TOP5": `m3Sales ≥ 내 등급 min`인 인플루언서들의 캠페인(LIVE/CLEARING/SETTLED) 확정 매출 + 데모 기본값(`base`)을 상품별로 합산한 뒤, **실사진(누끼) 상품 우선(`realFirst`) → 합산 매출 내림차순**으로 5개 — 순수 매출 상위 5개가 아니다. 내 등급이 높을수록 표본이 좁아진다.
- 상품 카드와 상세 모달 헤더에 브랜드 칩 옆 브랜드 등급 뱃지(5.4절).
- 상품 카드·상세의 수수료 표기 "수수료 X~Y%"에서 Y = X + `GRADES[0].bonus`(블랙 +3%p). 브랜드 상품 등록 폼도 "등급 보너스 포함 최대 N% (블랙, 보너스는 플랫폼 부담)"으로 안내.
