# 셀러리 샘플 정책

> 최종 수정: 2026-09-14 · 근거: 코드 상수(js/00-core.js, js/02-state.js 등) + 브랜드/인플루언서 제안서(2026.09) · 상태: 프로토타입 기준(실서비스 전 확정 필요)

샘플은 모든 판매(캠페인)의 첫 단계입니다. 인플루언서는 상품을 직접 써본 뒤 판매 진행 여부를 정하며, **샘플을 받았다고 판매 의무가 생기지 않습니다.** 이 문서는 프로토타입 코드가 실제로 구현한 규칙을 기준으로 쓰였고, 제안서와 다른 부분은 각 항목에 `제안서 표기:`로 병기했습니다.

---

## 1. 기본 원칙

| 구분 | 조건 | 결제 | 브랜드 승인 | 월 한도 차감 |
|---|---|---|---|---|
| **무상 샘플** | 내 등급 ≥ 상품별 기준 등급 · 상품당 1회 · 이달 한도 내 | 없음 | 필요(승인 후 발송) | 차감 |
| **샘플 구매** | 위 조건 중 하나라도 미충족 | 현금 또는 🥬 셀러리 | 불필요(결제 즉시 발송 단계) | 미차감 |
| **브랜드 직접 제안** | 브랜드(또는 자동 제안)가 먼저 제안 | 없음 | 불필요(수락 즉시 발송 단계) | 미차감 |

- 무상 샘플은 세 조건(`freeEligible` · `!hadFreeSample` · `sampleLeft > 0`)을 **모두** 충족해야 하며, 하나라도 빠지면 버튼이 자동으로 "샘플 구매 ₩N"으로 바뀝니다.
- 상품에 독점 인플루언서가 확정된 경우(`exclusiveSellerId`) 다른 인플루언서는 무상·구매 모두 불가("독점 잠김").
- 같은 상품에 진행 중인 캠페인(`REJECTED` · `PASSED` · `DECLINED` · `SETTLED` 제외)이 있으면 "진행 중"으로 잠깁니다.
- 노출 중(`listed`) 상품만 갤러리에 나타나므로, 브랜드가 노출을 중단하면 새 샘플 요청이 막히고 직접 제안 수락도 거부됩니다.

## 2. 상태 흐름

캠페인 상태(`ST`) 중 샘플 단계에 해당하는 것:

| 상태 | 화면 라벨 | 차례 | 진입 조건 |
|---|---|---|---|
| `SAMPLE_REQUESTED` | 샘플 요청 | 브랜드 | 인플루언서가 무상 샘플 요청 |
| `INVITED` | 브랜드 제안 · 수락 대기 | 인플루언서 | 브랜드 직접 제안 / 자동 제안 |
| `REJECTED` | 거절됨 | — | 브랜드가 샘플 요청 거절 |
| `DECLINED` | 제안 거절 | — | 인플루언서가 브랜드 제안 거절 |
| `SAMPLE_APPROVED` | 샘플 발송 대기 | 브랜드 | 브랜드 승인 또는 제안 수락 |
| `SAMPLE_PURCHASED` | 샘플 구매 · 발송 대기 | 브랜드 | 인플루언서가 샘플 구매 결제 |
| `SAMPLE_SHIPPED` | 샘플 배송중 | 인플루언서 | 브랜드가 운송장 입력 |
| `TESTING` | 테스트 중 | 인플루언서 | 인플루언서 수령 확인(기한 14일) |
| `PASSED` | 인플루언서 패스 | — | 테스트 후 진행하지 않기로 선택 |

스텝퍼(`FLOW`)는 `샘플요청 → 샘플승인 → 배송 → 테스트 → 일정제안 → …` 순이며, `SAMPLE_PURCHASED`는 "샘플승인" 칸에, `INVITED`는 "샘플요청" 칸에 표시됩니다.

## 3. 무상 샘플 기준 등급 (`samplePolicy` · `spOf`)

브랜드는 상품마다 `samplePolicy`를 지정합니다(상품 등록·수정 폼의 "🎁 샘플 정책" 카드).

| 필드 | 값 | 의미 |
|---|---|---|
| `freeGrade` | 스타터 ~ 블랙 | 이 등급 **이상**이면 무상(1회). 폼 기본 선택값은 **실버**. 폼 `npFreeGrade`는 7개 등급만 제공하며 **"무상 미제공" 옵션은 없음**(저장 시 빈 값이면 실버) |
| `buyMode` | `auto` / `fixed` | 등급 미달 시 구매가 산정 방식 — 자동(판매가 − 인플루언서 수수료) / 브랜드 지정가 |
| `fixedPrice` | 원 | `fixed`일 때 구매가. 0이면 `auto`로 동작 |
| `refund` | true/false | 판매 확정 시 샘플 구매액 환급 여부 |
| `sample` (`samplePolicy` 밖의 상품 필드 `p.sample`) | 자유 텍스트 · 기본 `무상 1개` | **표시용 "샘플 내용" 문구** — 정책 로직과 무관. 폼 `npSample`(placeholder "예: 무상 1박스"), 시드는 `무상 1박스`·`무상 2주분`·`무상 1통`·`무상 1병`·`무상 3매` 등. 상품 카드(`· 샘플 {문구}`)·상품 상세 모달·브랜드 상품 목록 샘플 열에 항상 표시되고 관리자 상품 검색(`vAdminProducts`)의 검색 대상 |

- **구매 전용(무상 없음) 정책은 없습니다** — 제안서 표기: 브랜드 제안서 p.11 "샘플 정책 (무상 제공 기준 등급 **또는** 샘플 판매가)"는 무상 없이 구매 전용으로 운영하는 선택지를 시사하지만, 코드는 무상 기준 등급이 필수이고 무상 미제공 옵션이 없습니다(블랙 지정이 사실상 최소). **미정(코드 미구현)**.

`samplePolicy`가 없는 상품(시드 일부)은 `spOf()`가 **판매가 구간별 기본값**을 적용합니다. 폼의 "권장" 문구도 같은 구간입니다.

| 판매가(`gp`) | 기본 `freeGrade` |
|---|---|
| ₩30,000 미만 | 브론즈 |
| ₩30,000 ~ ₩79,999 | 실버 |
| ₩80,000 이상 | 골드 |

기본값의 나머지 필드는 `buyMode:'auto'` · `fixedPrice:0` · `refund:false`입니다.

**등급 비교 규칙** — `freeEligible(p,s)` = `tierIdx(내 등급) ≤ tierIdx(freeGrade)`. `GRADES` 배열은 블랙(0) → 다이아(1) → 플래티넘(2) → 골드(3) → 실버(4) → 브론즈(5) → 스타터(6) 순이므로 인덱스가 작을수록 상위 등급입니다.

## 4. 월 한도 (`sampleQuota` · `sampleUsed` · `sampleLeft`)

| 인플루언서 등급 | 월 무상 요청 한도 |
|---|---|
| 스타터 · 브론즈 | 1회 |
| 실버 · 골드 | 2회 |
| 플래티넘 · 다이아 · 블랙 | 5회 |

- 경계는 `tierIdx` 기준: `i ≤ tierIdx('플래티넘')` → 5, `i ≤ tierIdx('실버')` → 2, 그 외 1. `GRADES`의 `perk` 문구("샘플 월 N회")와 일치합니다.
- **사용량(`sampleUsed`)** = 이번 달(`createdAt`의 `YYYY-MM` = 오늘의 `YYYY-MM`)에 만든 내 캠페인 중 `invited`도 `purchased`도 아닌 건의 수. 상태를 보지 않으므로 **브랜드가 거절한 요청(`REJECTED`)도, 패스한 건도 한도를 차지**합니다.
- **잔여(`sampleLeft`)** = `max(0, 한도 + sampleExtra − 사용량)`. 달이 바뀌면 사용량 집계가 자동으로 0부터 시작합니다(별도 리셋 로직 없음).
- `sampleExtra`(셀러리로 산 추가 횟수)는 `buyItem('sample')`에서만 증가하지만 현재 `SHOP.seller`에 `id:'sample'` 항목이 없어 **구매 경로가 닫혀 있습니다**(잔존 코드). 같은 이유로 "무제한" 표시 분기(`Infinity`)도 실제로는 도달하지 않습니다.
- 재판매 캠페인(`regongu`)은 `invited`/`purchased` 플래그 없이 생성되어 **그 달의 사용량에 포함**됩니다 — 샘플 단계를 생략하는 흐름인데도 한도를 소모하므로 실서비스 전 정리 필요.

## 5. 상품당 무상 1회 (`hadFreeSample`)

같은 상품 × 같은 인플루언서의 캠페인 중 `purchased`·`invited`가 아니고 상태가 `REJECTED`·`DECLINED`가 **아닌** 건이 하나라도 있으면 "이미 받음"으로 봅니다.

| 이전 결과 | 다음에 같은 상품 요청 시 |
|---|---|
| `REJECTED` (브랜드 거절) | 무상 재요청 가능(단, 거절된 요청의 월 한도 차감은 유지) |
| `PASSED` (테스트 후 패스) | 무상 소진 → 샘플 구매로만 진행 |
| `SETTLED` (판매 완료) | 무상 소진 → 샘플 구매 또는 재판매(샘플 생략) |
| 구매 샘플 / 브랜드 제안 | 무상 1회에 영향 없음 |

## 6. 무상 경로: 요청 → 승인 → 발송 → 수령

1. **요청** (`ACT.reqSample`) — 검사 순서: 독점 확정 → `freeEligible` → `hadFreeSample` → `sampleLeft`. **독점 확정**(`exclusiveSellerId`가 다른 인플루언서)이면 토스트("이 상품은 독점 인플루언서가 확정되어 샘플 요청이 제한됩니다")만 띄우고 **종료** — 구매 모달은 열리지 않음(구매 불가, §1 "독점 잠김"과 동일). `freeEligible` · `hadFreeSample` · `sampleLeft` 중 하나라도 걸리면 토스트 안내 후 **샘플 구매 모달**로 넘어갑니다. 모두 통과하면 `SAMPLE_REQUESTED` 캠페인 생성 + 스레드로 이동.
2. **브랜드 검토** — 스레드 카드에 인플루언서 채널·팔로워·등급이 표시되고, 승인(`approveSample`) 시 `SAMPLE_APPROVED`("배송지 전달됨" — **문구만**, 실제 주소 데이터 없음 · §14 "샘플 배송지" 참조), 거절(`rejectSample`) 시 `REJECTED`. 인플루언서 화면 안내 문구상 "브랜드가 … 보통 24시간 내 응답".
3. **발송** (`shipSample`) — 브랜드가 운송장 번호를 입력(비우면 `6890-XXXX-XXXX` 형식 임의 생성) → `SAMPLE_SHIPPED`. 운송장은 **인플루언서 요청함**(`sellerRequests`, `SAMPLE_SHIPPED`일 때 `· 운송장 N`)과 **캠페인 스레드 카드**(`운송장 N · 수령 확인 시 테스트 기한 14일이 시작됩니다.`)에 표시됩니다. 홈 "지금 할 일"(`vSellerHome`)에는 `샘플 수령 확인` 라벨만 뜨고 운송장은 표시되지 않습니다.
4. **수령 확인** (`receiveSample`) — 인플루언서가 누르면 `testDue = 오늘 + 14일`, 상태 `TESTING`.

## 7. 샘플 구매 (유상)

### 7.1 언제 구매로 넘어가나

버튼이 "샘플 구매 ₩N"으로 바뀌며 툴팁에 이유가 붙습니다: `무상 기준 등급 미달` / `무상 샘플은 상품당 1회` / `이달 무상 한도 소진`.

### 7.2 구매가 (`samplePrice`)

| `buyMode` | 구매가 |
|---|---|
| `auto` | `Math.round(판매가 × (1 − 인플루언서 요율) / 10) × 10` — **10원 단위 반올림**(`.5`는 올림) |
| `fixed` (`fixedPrice > 0`) | 브랜드 지정가 그대로 |

- 인플루언서 요율(`p.rate`)은 브랜드가 정한 총 수수료율(폼 `npRate`, 입력 범위 **11~50%**)에서 플랫폼 10%p를 뺀 값이며, **최소 5%**로 보정됩니다(`Math.max(5, 총 수수료율 − 10) / 100` — `saveProduct`·`createProduct` 동일). 자동 구매가는 이 `p.rate`에 연동됩니다. 모달에는 "판매가 − 내 수수료 N% = 샘플 구매가"로 풀어서 보여줍니다.
- 예: GL-01 ₩89,000 × (1 − 0.15) = ₩75,650 / 벨리라잇 ₩24,900 × 0.82 = ₩20,418 → ₩20,420 / 시카 세럼은 자동 산정 시 ₩25,425 → ₩25,430이지만 지정가 ₩15,000 적용.
- 폼·모달의 "브랜드 지정가 **(1회 한정)**" 문구는 코드에서 횟수를 제한하지 않습니다 — **미정(코드 미구현)**.

### 7.3 결제 수단 (`sampleSplit` · `SAMPLE_CEL_WON`)

| 수단 | 규칙 |
|---|---|
| 현금 (셀러리 안전결제) | 구매가 전액 |
| 🥬 셀러리 우선 결제 | `cel = floor(구매가 / 20,000)`, 나머지는 현금. 1🥬 = ₩20,000 (`SAMPLE_CEL_WON`) |

- 셀러리 옵션은 `cel > 0`이고 보유 🥬 ≥ `cel`일 때만 활성(기본 선택). 구매가가 ₩20,000 미만이면 "해당 없음"으로 비활성, 보유가 모자라면 "셀러리 N개가 필요해요 — 셀러리 샵에서 충전" 안내.
- 예: ₩75,650 → 🥬 3 + ₩15,650 / ₩23,920 → 🥬 1 + ₩3,920 / ₩19,600 → 현금만.

### 7.4 구매 후 처리 (`ACT.confirmSampleBuy`)

- 캠페인 `SAMPLE_PURCHASED` 생성(`purchased:true`, `samplePaid:{price,cel,cash,method}`), 🥬 사용분은 원장에 차감 기록.
- 주문 1건이 `sample:true` · `PAID`로 추가되어 **브랜드는 일반 판매 1건과 동일하게 정산**받습니다.
- 브랜드 승인 단계 없이 바로 "발송 처리(구매 완료)" 카드로 넘어가며, 이달 무상 한도와 상품당 1회를 소모하지 않습니다.
- **내비 배지 불일치(코드 정리 필요)** — 상단 내비 배지용 `counts()`는 브랜드 대기 건을 `SAMPLE_REQUESTED`·`SCHEDULE_PROPOSED`·`SAMPLE_APPROVED`(+ 독점 요청·CS)로만 세어 **`SAMPLE_PURCHASED`가 배지에 잡히지 않습니다**. 브랜드 요청함(`brandPending`)은 `SAMPLE_PURCHASED`를 포함하므로 요청함 건수와 배지가 다릅니다. 인플루언서 쪽 배지는 `INVITED`·`SAMPLE_SHIPPED`·`TESTING`만 세고 `SAMPLE_APPROVED`·`SAMPLE_PURCHASED`는 세지 않는데, `sellerPending`도 이 둘을 "응답 필요 N건"에서 빼고 정보성(`info`) 행으로만 목록에 넣으므로 인플루언서 쪽은 "응답 필요" 수와 배지가 같고 목록 행 수만 다릅니다.

### 7.5 정산에서의 취급 (`calc`)

| 항목 | 샘플 구매분 적용 |
|---|---|
| PG 수수료 1.9% | 적용(브랜드 정산에서 차감) |
| 플랫폼 수수료 10% | 적용 |
| 인플루언서 수수료 · 등급 보너스 | **0** (`net − sampleNet`에만 적용) |
| 🥬 결제분 | 브랜드에는 원화로 정산, 🥬 × ₩20,000은 **플랫폼 부담** — 관리자 매출·순수익의 "비용 집계" 변동비 행 `샘플 셀러리 결제 보전`(`celCover` = Σ `samplePaid.cel` × ₩20,000, 상태 무관 전 캠페인 합산, 비고 "인플루언서가 🥬로 낸 샘플값을 브랜드에 원화 지급") |
| 관리자 환불 | 불가 — "캠페인 스레드에서 협의" 토스트 |

화면별 표시 라벨은 다릅니다:

| 화면 | 행 라벨 |
|---|---|
| 캠페인 정산 미리보기(`detActions` 스레드) | `└ 샘플 구매분 (인플 수수료 0)` — `sampleNet`이 있을 때만 |
| 관리자 매출·순수익 "손익 요약" | `└ 인플루언서 샘플 구매분` (비고 `인플 수수료 0 · 플랫폼 10% 동일`) |
| 관리자 매출·순수익 "비용 집계 → 최종 순이익" | `샘플 셀러리 결제 보전` −₩(`celCover`), 운영 비용 합계에 포함 |

**집계 범위** — 샘플 주문(`sample:true`)이 어디에 잡히는지:

- **브랜드 정산 목록·관리자 GMV에 즉시 포함** — 브랜드 정산 화면(`vBrandSettle`)과 관리자 매출·순수익(`vAdminRevenue`)은 `['LIVE','CLEARING','SETTLED'].includes(status) || c.samplePaid` 로 캠페인을 고르므로, 상태와 무관하게 **`SAMPLE_PURCHASED` 직후부터** 브랜드 정산 목록과 GMV(`T.net`)에 잡힙니다.
- **고객 노출 통계에서 제외** — 고객 홈 "오늘 주문"(`vCustHome`, `!o.sample`)과 셀러리 소개 통계(`vCustAbout`, `orders.filter(o=>!o.sample)`)는 샘플 주문을 세지 않습니다.
- **판매 수량·결제 건수에는 포함** — `soldQty`(PAID 주문 qty 합)와 `calc.paidCnt`는 샘플 주문을 구분하지 않으므로, 구매 샘플 캠페인이 `LIVE`로 이어지면 "판매됨/잔여"와 "결제 N건"에 샘플 1개가 포함됩니다.

## 8. 환급 옵션 (`refund`)

브랜드가 상품에 `refund:true`("판매 확정 시 샘플 구매액 환급 (신규 인플루언서 유입용)")를 켜면 — 제안서 표기: 인플루언서 제안서 p.11 "정산에 자동 가산" → 실제는 **🥬/현금 분리 환급**(🥬는 🥬 원장으로, 현금분만 지급액 가산):

- **시점**: 그 캠페인이 `SETTLED`로 정산 실행될 때(`ACT.runSettle`) 1회. 조건 `samplePaid && spOf(p).refund && !sampleRefunded`. **매출 조건은 없습니다** — 주문 0건이어도 정산이 실행되면 환급됩니다("판매가 성사되면"의 판정 = 정산 실행 자체).
- **방법**: 🥬로 낸 만큼은 🥬로 원장에 돌려주고(`샘플 구매 환급 · 상품명`), 현금분만 인플루언서 지급액에 **가산**(`sellerPay = 수수료 × (1 − 원천징수) + 환급 현금` — 환급분에는 원천징수를 적용하지 않음). 예: 🥬 3 + ₩15,650을 낸 인플루언서는 ₩75,650이 아니라 **🥬 3 + ₩15,650**을 돌려받습니다.
- 스레드에 `🎁 샘플 구매액 환급 — 🥬 N + ₩M (판매 확정 조건 충족)` 기록, `sampleRefunded:true`로 중복 방지.
- 패스·미진행 시 환급 없음. 환급 여부는 **정산 시점의 상품 정책**을 봅니다(구매 후 브랜드가 옵션을 끄면 환급되지 않음). 브랜드는 진행 중·확정 판매가 있어도 샘플 정책을 수정할 수 있고(폼 notice "재고·샘플 정책·옵션·이미지·독점권은 수정 가능") `saveProduct`가 `samplePolicy`를 **재검수 없이** 덮어쓰므로, 제안서의 "환급 옵션을 켠 상품은 … 돌려받습니다"라는 보장은 코드상 성립하지 않습니다.

## 9. 브랜드 직접 제안 (`INVITED`)

- 브랜드 갤러리에서 제안(`confirmInvite`) 또는 자동 제안(`runAutoPropose`, `auto:true`)으로 `INVITED` 캠페인이 생깁니다(`invited:true`). 다이아·블랙 인플루언서에게는 제안권 🥬 10이 차감됩니다(`celUsed`). **제안 시 가드 3가지**: (1) 제안 모달(`inviteModal`)은 내 상품 중 **노출 중(`listed`)** 상품만 선택지로 주고, 없으면 토스트 "노출 중인 상품이 없습니다 — 상품을 먼저 등록하세요"로 막습니다. (2) `confirmInvite`는 **독점 확정 상품**(`exclusiveSellerId`가 다른 인플루언서)을 제안 불가 — 토스트 "이 상품은 독점 인플루언서가 확정되어 다른 인플루언서에게 제안할 수 없습니다". (3) 자동 제안 후보(`autoMatches`)는 `listed` 이면서 `exclusiveSellerId`가 없는 상품만 대상으로 하고, 같은 상품 × 인플루언서에 **진행 중 캠페인**(`REJECTED`·`PASSED`·`DECLINED`·`SETTLED` 제외)이 있는 조합은 제외합니다.
- **수락**(`acceptInvite`) → 브랜드 승인 없이 `SAMPLE_APPROVED`(메시지 "배송지 전달됨" — 문구만, 실제 주소 데이터 없음). 독점 확정 상품·노출 중단 상품은 수락 불가. 비공개(`hidden`) 인플루언서가 수락하면 스레드 시스템 메시지에 `🔓 익명 인플루언서 신원 공개 — 이름 핸들`이 기록되어 **해당 브랜드에게** 이름·핸들이 공개됩니다 — 프로필의 `hidden` 플래그는 그대로이므로(바꾸는 코드는 관리자 `admToggleHidden`뿐) 갤러리·스카우트·고객 화면에서는 여전히 비공개입니다.
- **거절**(`declineInvite`) → `DECLINED`, 사용된 제안권 🥬는 브랜드에 환급(`celRefunded`).
- `invited` 캠페인은 `sampleUsed`·`hadFreeSample` 집계에서 제외 — **월 한도·상품당 1회 모두 미차감**. 안내 문구: "수락 시 샘플 발송 단계부터 시작됩니다 (무상 · 이달 한도 미차감)". 브랜드 화면의 대기 카드 안내는 "인플루언서가 수락하면 … 보통 48시간 내 응답해요"(인플루언서의 응답 시간 안내, 코드 강제 없음).

## 10. 테스트 기한 · 패스

- **기한 14일**: `receiveSample`과 재판매 `regongu`에서 `addD(today(),14)`로 계산합니다. 이름 붙은 상수는 없고 리터럴 `14`가 두 곳에 있으며, 안내 문구도 "수령 확인 시 테스트 기한 14일이 시작됩니다"로 고정. 제안서 표기(14일)와 일치.
- 기한은 스레드·요청함·홈 할 일·캘린더("테스트 마감")에 표시될 뿐, **기한 경과 시 자동 패스·알림 등 처리는 없음** — 미정(코드 미구현).
- **패스**(`passCamp`) → `PASSED`. 코드상 등급·🥬·노출·다음 제안에 어떤 페널티도 없습니다(제안서 "등급·노출·다음 제안에 아무 영향이 없어요"와 일치). 다만 그 상품의 무상 1회는 소진되고, 요청 당시 차감된 월 한도는 되돌아오지 않습니다.
- **재판매**(`regongu`) — 지난 판매 성과 기반으로 샘플 단계를 생략하고 `TESTING`(기한 14일)부터 시작합니다.
