# MYR 운영 콘솔 — 화면 구성 (디자인 요청서)

2026-11-12 다시 씀 · 2026-11-17 자동 이체 기준으로 고침(§1-1 배지 · §1-3 용어집 · §3 홈 · §11 지급 · §12). **Claude Design 에 올려 운영 콘솔 UI/UX 시안을 받기 위한 문서**다. 화면마다 무엇이 보이고, 무엇을 누를 수 있고, 상태에 따라 어떻게 달라지는지를 적었다.
만들 때 필요한 것(서버 함수 · 스크립트 · 결정)은 [docs/myr-admin-plan.md](myr-admin-plan.md) — 거기서 화면마다 "screens §번호"로 이 문서를 가리킨다.

## 0. 디자인 방향

- **서비스**: Make Your Recipe(MYR) — 크리에이터가 자기 레시피로 건강식품을 만들어 팔고, MYR 이 제조 · 판매 · 배송 · CS 를 대신하는 샵.
- **이 콘솔을 쓰는 사람**: MYR 운영팀(몇 명). 매일 상품 심사 · 발송 · 교환/환불을 처리하고, 매월 1일 전후로 제조금액 입력 · 정산 확인을 한다. **크리에이터 지급은 자동 이체**(매일 오후 1시 · §11) — 운영은 세금계산서 수취 확인과 이체 실패 · 보류 같은 예외만 처리한다.
- **기기**: **PC 우선**(1280~1440px). 표 · 2열 비교 · 오른쪽 고정 패널이 많은 업무 화면. 모바일은 홈 · 목록 확인 정도만 깨지지 않게.
- **톤**: 크리에이터 콘솔 시안 "MYR Influencer Admin"(다크 배경 · 오렌지 포인트 · 둥근 카드 · 작은 상태 칩)과 같은 계열. 운영 화면이라 더 촘촘하게 — 표 한 줄 높이 · 숫자 정렬(오른쪽 · 고정폭 숫자) 우선.
- **글자**: 한국어 · 금액은 `₩74,100` · 날짜는 `11월 12일(목)` · 시각은 `오후 1시` · 기간은 "3일째".

## 1. 공통 구성

### 1-1. 메뉴

왼쪽 고정 사이드 메뉴(또는 상단 내비 — 시안에서 제안). 메뉴 옆에 처리할 건수 배지.

- **배지 숫자 = 홈 카드 숫자**(같은 기준 · 2026-11-17). 급한 건이 있으면 빨강, 기다리기만 하면 되는 건은 회색 숫자.
    - 지급: 결과 확인 필요 + 운영 조치 필요(빨강) · 계좌 확인 필요 — 재시도 대기는 자동이라 넣지 않는다 · 지급 보류는 회색.
    - 세금계산서: 확인 중 + 발행 기한 지남(빨강).
    - 문의 · 교환/환불: 24시간 넘은 문의 · 환불 다시 필요 · 크리에이터 답변 기한 넘김은 빨강.

### 1-2. 자주 나오는 모양

- **목록 화면**: 페이지 제목 + 요약 숫자 → 탭(상태별 · 건수) → 필터 줄(크리에이터 · 기간 · 검색) → 표 → 줄을 누르면 상세(페이지 또는 오른쪽 서랍).
- **상세 화면**: 왼쪽 본문(내용 · 표) + 오른쪽 고정 패널(상태 · 처리 버튼 · 이력).
- **상태 칩 색**(크리에이터 콘솔과 같은 규칙):
    - 민트 = 예정 · 대기 · 진행(지급 대기 · 송금 중)
    - 빨강 = 보류 · 요청 · 막힘(지급 보류 · 결과 확인 필요 · 운영 조치 필요 · 계좌 확인 필요 · 교환/환불 요청 · 제조금액 확인 중)
    - 주황 = 진행 · 주의(재시도 대기 · 상환 중 · 심사 N일째)
    - 회색 = 끝남(지급 완료 · 판매 종료 · 환불 완료)
- **되돌릴 수 없는 동작은 한 번 더 확인**: 첫 클릭에 버튼 줄이 `[취소] [정말 ○○하기]` 로 바뀐다(브라우저 확인창 없이 · 크리에이터 콘솔 반려/승인과 같은 방식). 반려 · 판매 종료 · 지급 완료 기록 · 지급 완료 취소 · 회수 확인 · 강제 종료.
- **사유 · 메모 입력**: 반려 · 정정 · 무효 · 운영 보류 · 지급 완료 취소 · 강제 종료는 사유가 필수 — 작은 모달 또는 패널 안 입력칸 + 글자 수.
- **민감 정보는 가린 값**: 연락처 `010-****-5678` · 계좌 `국민 ****5678` · 사업자번호 `***-**-12345`. 옆에 `[보기]` → 원문을 잠깐 보여 주고 "열람 기록이 남아요" 안내.
- **서버가 거절할 때**: 버튼 아래(또는 토스트)에 이유 한 줄 + 고칠 값. 예: "적은 금액이 지급 건 금액과 달라요 — 지급 건 금액 ₩74,100", "이체한 날이 정산 계산일(12월 1일) 전이에요".
- **빈 상태**: 탭마다 한 줄 안내("실패한 지급 건이 없어요").
- **처리한 사람 · 시각**: 상태가 바뀐 곳에는 "운영 김○○ · 11월 12일 오후 3:20" 을 작게. 자동 처리는 "자동 · 11월 7일 오후 1:02".
- **글자 크기 · 대비**: 보조 글자(시각 · 빈 상태 · 표 열 제목 · placeholder)도 배경 대비 4.5:1 이상(흰 글자 투명도 최소 `.55`). 칩 · 배지는 12~13px. 모바일 버튼 터치 영역 44px 이상.

### 1-3. 상태 이름(용어집)

상태 하나에 이름 하나. 운영 콘솔과 크리에이터 콘솔은 같은 서버 상태를 다른 말로 보여 줄 수 있다 — 아래 표 밖의 이름(예: "지급할 차례" · "지급일 지남" · "결제 완료"를 발송 대기 뜻으로)은 쓰지 않는다.

| 서버 상태 | 운영 콘솔 | 크리에이터 콘솔(만들어져 있음 · 0111) |
|---|---|---|
| 지급 건 · 보낼 수 있음 | 지급 대기 | 지급 예정 |
| 지급 건 · 보류 | 지급 보류 + 이유 전부 | 지급 보류 |
| 이체 · 송금 중 | 송금 중 | 지급 중 |
| 이체 실패 · 잠깐 안 됨 | 재시도 대기 | 지급 지연 |
| 이체 실패 · 계좌 문제 | 계좌 확인 필요 | 지급 실패 |
| 이체 실패 · 잔액 · 한도 | 운영 조치 필요 | 지급 확인 중 |
| 이체 실패 · 결과 불명 | 결과 확인 필요 | 지급 확인 중 |
| 지급 건 · 끝남 | 지급 완료 | 지급 완료 |
| 지급 건 · 0원 | 지급 없음 | 지급 없음 |
| 주문 줄 · 발송 전 | 발송 대기 | — |

- 크리에이터에게는 운영 쪽 실패 원인(잔액 · 한도 · 결과 불명)을 보여 주지 않는다 — "운영팀이 지급을 확인하고 있어요".
- 보류와 이체 실패가 겹치면: 운영 콘솔은 **둘 다** 칩으로(보류 중에는 자동 재시도하지 않는다는 안내) · 크리에이터 콘솔은 "지급 보류"만.

## 3. 홈 대시보드

**무엇**: 오늘 처리할 일을 숫자 카드로. 카드를 누르면 그 목록(필터가 걸린 채)으로 간다. 지급은 자동 이체(§11)라 홈은 "보낼 것"이 아니라 **막힌 것 · 예외**를 맨 위에 둔다(2026-11-17).

**모든 카드의 모양**: 건수 · **가장 오래 기다린 시간**("3일째" · "26시간") · 바로가기. 금액은 오른쪽이나 아래 작은 글자 — 건수와 기다린 시간이 먼저다.

**① 맨 위 — 돈 예외**(있을 때만 · 빨강 카드 · 다른 카드보다 먼저)
- **이체 결과 확인 필요** N — 송금 결과를 모른다. 다시 보내면 두 번 나갈 수 있어 [결과 조회]가 먼저.
- **운영 조치 필요(잔액 · 한도)** N — 그날 이체가 막힌다. 충전 · 한도 조정 뒤 다시 보내기.
- **환불 다시 필요** N — 카드사 환불 실패 등.
- **자동 실행이 안 돌았어요** — 정산 크론(매월 1일) · 이체 크론(매일 오후 1시)의 마지막 실행이 예정 시각보다 늦으면 경고 한 줄 + 마지막 실행 시각.

**② 오늘 오후 1시 자동 이체**(카드 하나 · 항상)
- 보낼 예정 N건 · ₩합계(지급 대기 건 + 재시도 대기 건 — 지급 대기는 사업자 정보 · 세금계산서까지 확인돼 보류 이유가 없는 건).
- **지급대행 잔액** ₩○ — 보낼 금액보다 적으면 빨강 "잔액이 ₩○ 모자라요"(서비스가 정해지면 · §13).
- 마지막 실행: "오늘 오후 1:02 · 성공 5 · 실패 1" → 지급 목록(그 날짜)으로. 오후 1시 전이면 어제 결과.

**③ 묶음 카드**(묶음마다 제목 · 카드 2~5개 · 급한 카드는 빨강 테두리)

| 묶음 | 카드 |
|---|---|
| 상품 | 신규 심사 대기 N(가장 오래 "3일째") · 수정 심사 대기 N · 재고 0 판매 중(품절) N |
| 주문 · 배송 | 발송 대기 N · 배송 완료 기록 없는 출고 N(정산에 못 들어간다 — 월말 · 정산 3일 전부터 빨강) |
| 문의 · 교환/환불 | 답변 없는 문의(24시간 넘음 · 빨강) N · 회수 대기 N · 재발송 대기 N · 크리에이터 답변 기한 넘김(빨강) N |
| 크리에이터 | 새 초대 요청 N · 사업자 · 정산 정보 확인 대기 N(계좌 확인 필요 실패가 걸린 크리에이터는 따로 표시 — 확인하면 다음 오후 1시에 다시 보낸다) |
| 정산 | 다음 정산 확정(매월 1일 오후 1시 · D-N) · 제조금액 미입력 판매 중 상품 N · 보류된 정산 N |
| 세금계산서 | **확인 중 N**(가장 오래 기다린 시간 · "지금 확인하면 오늘 오후 1시 지급" — 오후 1시가 지났으면 "내일 오후 1시") · **발행 기한(다음 달 10일) 지났는데 안 낸 크리에이터 N**(빨강) · 다시 제출 요청한 뒤 아직 안 낸 N |
| 지급 | 계좌 확인 필요 N · 재시도 대기 N(회색 · "다음 오후 1시에 자동으로 다시 보내요") · 지급 보류 N(이유별: 운영 보류 · 사업자 정보 확인 전 · 세금계산서 확인 전) · 송금 중 N |

- 홈에 넣지 않는 것: "지급할 차례" · "지급일이 지났는데 지급 완료 기록이 없는 건"(수동 이체 기준 — 자동 이체에서는 없다) · 수동 [지급 완료 기록] · [이체용 내려받기](§11 예외 처리에만).

**④ 이번 달 정산 흐름**(진행 막대 · 날짜보다 건수)
- 정산 확정(○월 1일 오후 1시 · 확정 N · 보류 N) → 세금계산서 제출(○월 10일까지 · 제출 N / 필요 N · 기한 지남 N) → 수취 확인(확인 N) → 자동 이체(매일 오후 1시 · 지급 완료 N / 지급 건 N · 실패 N · 보류 N) → 다음 정산 확정(D-N).
- 지급은 "매월 1일"이 아니라 **세금계산서 확인 다음 오후 1시**에 건마다 나간다 — 흐름에 지급 날짜를 하나로 적지 않는다.

**모바일**: 강조는 모바일에서 끝낼 수 있는 일(문의 답변 · 지급 보류 해제 · 배송 완료 확인)에 둔다. PC 에서만 되는 일(상품 심사 · 송장 일괄 입력)은 건수만 보여 주고 "PC 에서 처리" 표시. 화면 제목과 하단 탭 선택 표시는 모든 화면에서 보인다.

## 4. 상품

### 4-1. 상품 목록

- **탭**: 신규 심사 · 수정 심사 · 판매 중 · 일시중지 · 반려 · 판매 종료(건수). 임시저장은 필터로만.
- **정렬**: 심사 탭은 오래 기다린 순, 나머지는 최근 수정순.
- **표 줄**: 사진 · 상품명 · 크리에이터(@핸들) · 카테고리 · 가격 · 상태 칩 · "심사 N일째" 또는 "N일 전 승인" · 재고(남은 수량 · 0 이면 "품절" 빨강) · 판매 중인데 수정 심사가 걸려 있으면 "수정 심사 중" 칩도 같이.
- **필터**: 크리에이터 · 카테고리 · 검색(상품명 · 코드).

### 4-2. 신규 심사 상세

- **왼쪽 — 샵 상세 미리보기**: 고객이 보는 상품 페이지와 같은 순서로 그린다 — 구매 패널(사진 · 이름 · 가격 · 옵션) → 레시피 노트 → 01 왜 만들었나요 → 02 성분 → 03 섭취법 → 04 제품 정보 → 05 FAQ. 비어 있는 선택 섹션은 "비어 있음(샵에서 숨김)" 회색 블록.
    - 섹션 블록마다 오른쪽 위 **[의견 달기]** — 누르면 오른쪽 패널 의견 목록에 그 섹션이 골라진 새 줄이 생긴다. 의견이 달린 섹션은 테두리 강조.
- **오른쪽 — 검수 패널(고정)**:
    - 크리에이터(이름 · 핸들 · 연락처 가림) · 제출 시각 · 이전 반려 이력(있으면 그때 의견 접어서).
    - **의견 목록**: 줄마다 [섹션 고르기(1 기본 정보 ~ 7 FAQ · 전체)] + 문장 입력 · 삭제. 최대 10개 · 줄당 300자.
    - **자주 쓰는 의견** 칩(누르면 문장이 채워짐): "효능 · 최상급 표현", "의약품 오인 표현", "함량 근거 필요", "사진 해상도" 등(문구는 운영팀이 정한다).
    - **[반려]** — 의견 1개 이상 필요 · 한 번 더 확인.
    - **[승인]** — 누르면 **재고 입력**을 받는다(필수 · 0 이면 "샵에서 품절로 보여요" 경고) → 한 번 더 확인.
- **크리에이터 쪽에서는**: 반려되면 "심사 결과" → "반려 내용 고치기"(의견 달린 섹션에 "수정 필요" 칩) — 디자인 참고용.

### 4-3. 수정 심사(판매 중 상품의 수정본)

- **머리**: "수정 심사" 칩 · 요청 시각 · 안내 "승인 전까지 샵은 지금 내용으로 판매 중이에요".
- **본문 — 2열 비교**: 왼쪽 "지금 샵" · 오른쪽 "수정본". **바뀐 섹션만 펼쳐 강조**(바뀐 글자 표시), 안 바뀐 섹션은 접힌 한 줄.
- **오른쪽 패널**: 4-2 와 같은 의견 목록(기본 대상 = 바뀐 섹션) · 이 상품의 지난 수정 이력(반려 · 반영 · 취소).
- **[반영 승인]** · **[반려]** — 둘 다 한 번 더 확인. 반영해도 판매 상태 · 재고 · 옵션은 그대로라는 안내.
- 그사이 판매 종료된 상품이면 이 화면에 오지 않는다 / 승인 때 "상품 상태가 바뀌었어요" 거절 안내.

### 4-4. 상품 관리(같은 상세 화면 · 판매 중 · 일시중지 · 반려 · 종료)

- **판매 중 · 일시중지**: 오른쪽 패널 버튼 — [일시중지] / [다시 판매] · **[재고 수정]**(숫자 입력 · 0 이면 품절 안내) · **[판매 종료]**(되돌릴 수 없음 · 한 번 더 확인 · 열린 수정본은 취소된다는 안내).
- **제조 원장 칸**(→ §10-1 요약): 제조금액 · 보증금 · 남은 제조금액 · 갚은 비율 막대 · [원장 열기].
- **반려**: 보낸 의견 목록(읽기). 크리에이터가 다시 요청하면 신규 심사로 돌아온다.
- **판매 종료**: 읽기 전용 · 주문 · 환불 이력 링크.

## 5. 크리에이터

### 5-1. 초대

- **[초대 보내기]** 패널: 이메일 · 보낸 사람 이름 → 보내면 초대 링크 + [링크 복사].
- **목록 탭**: 대기 · 가입 완료 · 만료 · 취소 · **요청됨**(만료된 링크에서 "새 초대 요청하기"를 누른 사람).
- **줄 동작**: [다시 보내기](이전 링크는 무효) · [취소].

### 5-2. 크리에이터 목록

- 표 줄: 이름 · 핸들 · 계정 연결 여부 · 상품 수(판매 중/전체) · **사업자 정보 상태 칩**(미입력 · 확인 대기 · 확인 완료 · 다시 입력 요청) · 활동 상태(활성 · 정지) · 가입일.
- 필터: 사업자 정보 상태 · 활동 상태 · 검색.

### 5-3. 크리에이터 상세

탭 또는 세로 구획:

- **기본**: 이름 · 핸들 · 연락처(가림 + 보기) · 가입일 · **[정지] / [복구]**(정지하면 크리에이터 콘솔이 정지 화면 · 새 상품 저장 불가 — 한 번 더 확인) · **[계정 연결]**(로그인 계정이 없는 크리에이터).
- **사업자 · 정산 정보**: 상호 · 사업자등록번호(가림 + 보기) · 대표자 · 세금계산서 이메일 · 정산 계좌(가림 + 보기) · 제출 시각.
    - 상태가 "확인 대기"면 **[확인 완료]** · **[다시 입력 요청](사유 필수)**.
    - 그사이 크리에이터가 정보를 바꿨으면 "정보가 바뀌었어요 — 새 값으로 다시 확인해 주세요" + 새 값으로 다시 그림.
    - 확인 · 요청 뒤 "이 크리에이터의 지급 건 N건이 지급 대기/지급 보류로 바뀌었어요" 결과 한 줄(운영 보류 · 지급 완료 건은 그대로).
- **상품**: 이 크리에이터 상품 목록(§4-1 표 축소판).
- **활동**: 문의 응답률 · 최근 주문.
- **정산 요약**: 상품별 남은 제조금액 · 갚은 비율 · 보증금 상태 · 최근 정산 회차.
- **지급 이력**: 회차(정산월)별 줄 — 금액 · 상태 칩(지급 대기 · 지급 보류 + 이유 · 지급 완료 · 지급 없음) · 이체한 날 · 계좌(가림) · 운영 메모 · 줄을 열면 기록/취소 이력.

## 6. 주문 · 배송

### 6-1. 주문 목록

- 탭: 결제 완료 · 입금 대기 · 발송(배송 중) · 배송 완료 · 환불.
- 필터: 기간 · 크리에이터 · 주문번호 검색.
- 표 줄: 주문번호 · 결제일 · 주문자(가림) · 상품(첫 상품 외 N) · 크리에이터 · 금액 · 상태 칩 · 송장.

### 6-2. 주문 상세

- **주문 줄 표**: 상품 · 옵션 · 크리에이터 · 수량 · 금액 · 줄 상태 · 환불 이력(사진 · 상세).
- **수취인 · 결제**: 수취인(가림 + 보기 · 열람 기록) · 결제 수단 · 가상계좌.
- **송장**: 택배사 · 운송장 입력 · [송장 저장] → 고객에게 배송 시작 메일 · 이미 있으면 [정정].
- **예외 환불**: 사유 필수 · 크리에이터에게 알림 · 진행 중인 교환/환불이 있으면 경고 띠.

### 6-3. 송장 일괄 입력

- CSV 끌어다 놓기(`주문번호,택배사,운송장`) → **미리보기 표**(줄마다 정상 · 오류 이유) → [N건 저장] → 결과(성공 N · 실패 N + 실패 줄 내려받기).

### 6-4. 배송 완료 예외

**무엇**: 배송 중으로 오래(기본 5일) 남은 출고 줄. 배송 완료가 찍혀야 정산에 들어가므로 운영이 택배 조회로 확인하고 직접 찍는다.

- 표 줄: 주문번호 · 크리에이터 · 상품 · 택배사 · 운송장(**택배 조회 링크**) · 발송 후 며칠 · 이벗 등록 여부.
- 줄 동작: **[배송 완료]** → 실제 배송일 입력(기본 오늘) → 그 주문의 배송 중 줄 전부가 완료.
- 머리 경고: 월말(정산일 전)에 이 목록이 비어 있지 않으면 빨강 띠 "정산 전에 확인해 주세요".

- 표 줄: 요청번호 · 주문번호 · 크리에이터 · 상품 × 수량 · 종류/사유 · 지금 단계 칩 · 접수 · 승인 시각 · 처리한 사람(크리에이터 · 운영) · 크리에이터 답변 기한(2일) 넘은 처리 대기는 빨강(표시만 — 운영 처리 조건이 아니다).

### 8-2. 요청 상세

- **왼쪽**: 고객 사진(크게 보기) · 상세 내용 · 크리에이터 메시지 · "주문 · 배송" 칸(요청 상품 · 함께 주문한 상품 · 줄 상태 — 크리에이터 콘솔과 같은 표) · 처리 타임라인(접수 → 승인 → 회수 → 환불/재발송).
- **오른쪽 패널(단계별 버튼)**:
    - 회수 대기 → **[회수 확인]**(한 번 더 확인 · 누르면 바로 환불이 나간다는 안내)
    - 재발송 대기 → **[재발송 송장 입력]**(택배사 · 송장 → 고객 메일)
    - 환불할 차례 → **[환불 다시]**
    - 처리 대기 → **[승인]** · **[반려]** — 운영이 기한과 관계없이 언제든 처리할 수 있다(2026-11-13 결정).
        - 크리에이터 콘솔과 같은 모양: 처리 방법 고르기(선택지 · 예상 환불 금액은 서버 값 — 차감 뒤 0원 이하인 부분 환불은 나오지 않는다) · 고객에게 보낼 메시지(승인은 선택 · 반려는 필수) · 한 번 더 확인.
        - 패널 위에 "운영이 대신 처리해요 — 고객 메일은 크리에이터가 처리할 때와 같아요" 안내.
        - 처리하면 크리에이터 콘솔 요청 상세 타임라인에 "운영팀이 처리" · 시각을 보여 준다(크리에이터 콘솔 쪽은 운영 콘솔을 만들 때 같이 고친다 · 지금은 없음).

## 10. 정산

정산은 매월 1일 오후 1시에 자동으로 계산 · 확정된다(화면에 [확정] 버튼 없음). 판매가의 60% 가 정산금, 크리에이터가 갚을 **제조금액**을 상품별로 먼저 빼고(상계), 다 갚으면 **보증금**(제조금액의 25%)을 돌려준다. 제조금액이 아직 입력되지 않은 상품은 **보류**된다.

### 10-1. 제조 원장

- **맨 위 — 입력 대기**(빨강 카드 두 묶음):
    1. **보류된 정산** — 상품 · 크리에이터 · 보류된 달 · 정산금 합계 · [제조금액 입력] → [보류 확정]. 확정 버튼 옆 안내: "다음 정산 확정(○월 1일)에 포함돼요".
    2. **판매 중인데 원장이 없는 상품** — "다음 정산에서 보류될 후보 · 매월 1일 전에 채워 주세요".
- **상품별 원장**(목록 → 상품 열기):
    - 요약: 제조금액 합 · 상계한 금액 · **남은 제조금액** · 갚은 비율 막대 · 보증금(입금 확인 · 입금 전 · 환급 완료).
    - **차수 표**: 차수 · 제조금액 · 보증금(25%) · 보증금 입금 확인일 · 환급 여부 · 메모 · 입력자 · 무효면 줄 긋기 + 사유.
    - 버튼: **[제조 차수 추가]**(재생산도 같은 버튼 · 0원 = "제조금액 없음") · **[보증금 입금 확인]**(날짜) · 줄마다 **[금액 정정]**(올바른 금액 · 사유) · **[무효]**(사유).
    - 정정 · 무효 결과 안내: "이미 상계한 ₩60,000 보다 작아 정정할 수 없어요 — 크리에이터에게 ₩60,000 을 따로 지급해야 해요" · "보증금 차액 ₩5,000 — 따로 돌려주거나 받아 주세요".
- 목록 필터: 남은 제조금액 있음 · 다 갚음 · 보증금 미입금 · 원장 없음.

### 10-2. 월 정산 — 회차 목록

- 표 줄: 정산월 · 계산 시각 · 누가(자동 · 운영) · 상품 수 · 확정/보류 수 · 정산금 합 · 상계 합 · 보증금 환급 합 · **지급 합계** · 지급 진행(지급 완료 N / 지급 건 N · 보류 N 막대).
- 머리 버튼: [회차 수동 실행](자동 실행이 실패했을 때만 · 끝난 달만).
- 경고 띠: 배송 완료 기록 없는 출고 · 원장 없는 판매 상품 · 사업자 정보 확인 전 크리에이터.

### 10-3. 월 정산 — 회차 상세

- **크리에이터별 묶음**(접고 펼치기). 묶음 머리줄 = **그 회차 지급 건**: 금액 · 상태 칩(지급 대기 · 지급 보류 + 이유 · 지급 완료 · 지급 없음) · 지급 가능 여부 · 이체한 날 · [지급 건 열기](→ §11).
- **상품 줄 표**: 상태(확정 · 보류) · 판매 · 정산 뒤 환불 · 이월 · 정산금(60%) · 남은 제조금액(전) · 상계 · 남은 제조금액(후) · 보증금 환급 · 지급액.
    - 줄 표시: "○월분 · 보류 해제"(지난 달 보류가 이 회차에 풀린 줄) · "○월 정산 확정에 포함"(이 달 줄인데 다른 회차에 들어간 줄 — 흐리게) · "다음 정산 확정에 포함"(크리에이터 콘솔과 같은 말).
    - 그래서 크리에이터 지급 건 금액과 줄 지급액 합이 다를 수 있다 — 머리줄에 작은 설명.
- **줄 펼쳐 보기**: 주문번호 · 고객(가림) · 배송 완료일 · 단가(공구 표시) · 수량 · 금액 · 판매/정산 뒤 환불 구분.

## 11. 지급

**무엇**: 크리에이터에게 돈을 보내는 곳. 크리에이터마다 회차당 **지급 건** 1건. **자동 이체(2026-11-13 결정)** — 매일 오후 1시(정산 크론 바로 뒤) 세금계산서까지 확인된 지급 건을 보낸다 · 첫 기회는 매월 1일 오후 1시. 화면은 자동 지급 기준으로 그린다: 송금 중 · 지급 완료 · **지급 실패(종류: 재시도 대기 · 계좌 확인 필요 · 운영 조치 필요 · 결과 확인 필요)** · 지급 보류. 수동 [지급 완료 기록] · [이체용 내려받기]는 예외 처리용. 크리에이터 콘솔에는 운영 쪽 실패 원인 대신 "운영팀이 확인하고 있어요"만 보인다.

지급 건 상태(이름은 §1-3): **지급 대기**(보류 이유 없음 · 다음 오후 1시에 자동으로 보낸다 — 오후 1시 전에 세금계산서가 확인되면 그날) · **송금 중** · **지급 실패**(종류 아래) · **지급 보류**(이유: 사업자 · 정산 정보 확인 전 / 운영팀 확인 중 / 세금계산서 확인 전) · **지급 완료** · **지급 없음**(0원 — 정산금이 전부 제조금액 상계).

지급 실패 종류 — 종류마다 할 일이 다르다:

| 종류 | 무슨 일 | 자동으로 | 운영이 할 일 | 버튼 |
|---|---|---|---|---|
| **결과 확인 필요**(빨강 · 맨 위) | 송금 결과를 모른다(응답 없음 등) | 다시 보내지 않는다 | 지급대행에서 결과 조회 → 나갔으면 지급 완료 · 안 나갔으면 다시 보내기(같은 요청 키) | [결과 조회] — 조회 전에는 [다시 보내기] 없음 |
| **운영 조치 필요**(빨강) | 잔액 부족 · 한도 초과 등 운영 쪽 | 다시 보내지 않는다 | 충전 · 한도 조정 | [다시 보내기](지금) · 또는 다음 오후 1시를 기다림 |
| **계좌 확인 필요**(빨강) | 예금주 불일치 · 없는 계좌 | 다시 보내지 않는다 | 크리에이터가 계좌를 다시 입력 → 정산 정보 확인(§5) → 확인되면 다음 오후 1시에 자동 | [크리에이터 열기] |
| **재시도 대기**(주황) | 은행 점검 등 잠깐 안 됨 | 다음 오후 1시에 다시 보낸다 | 없음(여러 번 실패하면 운영 조치 필요로) | 없음 · 시도 횟수 표시 |

### 11-1. 지급 목록

- **머리**: 정산월 고르기 · 요약(지급 합계 · 자동 지급 완료 N/N건 · 실패 N · 보류 N) · **오늘 오후 1시 예정 N건 · ₩합계 · 지급대행 잔액**(모자라면 빨강 · §3 ②와 같은 값) · 마지막 실행 결과.
- **탭**: **지급 실패**(실패가 있으면 기본 · 종류별 하위 필터) · 지급 보류(이유별 하위 필터 — 이유가 하나라도 걸린 건이 나온다) · 지급 대기 · 송금 중 · 지급 완료 · 지급 없음 · 전체.
- **표**(한 줄 40~48px · 열 제목 · 정렬): 체크박스 · 크리에이터(이름 · @핸들) · 금액 · 담긴 줄 수("지난 달 보류분 포함" 표시) · 상태 칩 · 실패 종류 · 보류 이유 · 시도 횟수 · 마지막 시도 시각 · 계좌(가림 + 보기) · 지급일 · 메모 · 줄 끝 버튼.
    - 보류 이유는 걸린 것 **전부**를 보여 준다(예: "운영팀 확인 중 · 사업자 · 정산 정보 확인 전 · 세금계산서 확인 전"). 운영 보류가 있으면 맨 앞, 그다음 사업자 정보 → 세금계산서 순.
    - 보류와 실패가 겹치면 칩 둘 다 + "보류 중이라 자동으로 다시 보내지 않아요".
- **줄 끝 버튼**(상태별):
    - 지급 실패 → 위 표의 버튼
    - 지급 대기 → [운영 보류]("오늘 오후 1시 전에 걸면 이번 이체에서 빠져요")
    - 송금 중 → 없음("은행 처리 중")
    - 지급 보류(운영 보류) → [보류 해제] · 다른 이유도 걸려 있으면 "해제해도 ○○ 때문에 계속 보류돼요" 안내(해제하면 남은 이유로 자동 보류)
    - 지급 보류(사업자 정보 · 세금계산서) → 버튼 없음 · "정보가 확인되면 자동으로 지급 대기가 돼요" + [크리에이터 열기] · [세금계산서 열기]
    - 지급 완료 → [지급 완료 취소](수동 기록만 · 자동 이체 완료 건은 취소 대신 운영 메모)
    - 지급 없음 → 없음
- **여러 줄 선택** → 아래 고정 바 "N건 선택 · ₩합계 · [운영 보류] · [다시 보내기](운영 조치 필요만)".
- **예외 처리**(머리 오른쪽 "더보기" 안 · 평소에는 숨김): [지급 완료 기록](지급대행 밖에서 직접 이체했을 때) · [이체용 내려받기](계좌 원문 · "열람 기록이 남아요").

### 11-2. 지급 완료 기록(모달 · 예외 처리)

자동 이체 밖에서 직접 보냈을 때만 쓴다(지급대행 장애 · 결과 확인 필요를 직접 이체로 정리할 때).


- 내용: 크리에이터 · 금액(지급 건 금액) · 받는 계좌(가림).
- 입력: **이체한 날**(기본 오늘 · 미래 날짜 막기) · **보낸 금액 확인**(금액을 다시 입력 — 틀리면 막힘) · 메모(선택).
- 버튼: [취소] [기록하기] → 한 번 더 확인 "정말 지급 완료로 기록할까요? 크리에이터 화면에 바로 보여요".
- 여러 건이면: 건별 금액 목록 + 합계 확인 + 같은 이체일 → 결과 화면(성공 N · 실패 N + 실패 이유 줄별).
- 거절 안내 예시: "지급 보류 중이에요(사업자 · 정산 정보 확인 전)" · "이미 11월 11일에 지급 완료로 기록됐어요" · "보낸 금액이 지급 건 금액(₩74,100)과 달라요" · "이체한 날이 정산 계산일(12월 1일) 전이에요" · "오늘 이후 날짜는 기록할 수 없어요".

### 11-3. 운영 보류 · 보류 해제 · 지급 완료 취소(작은 모달)

- **운영 보류**: 메모 필수("계좌 확인 요청" 등) · 안내 "크리에이터에게는 '운영팀 확인 중'으로만 보여요 · 메모는 운영만 봐요".
- **보류 해제**: 안내 "해제하면 지금 상태로 다시 정해져요(사업자 정보 확인 전이면 다시 지급 보류)".
- **지급 완료 취소**: 사유 필수 · 빨강 안내 "기록만 되돌려요. 이미 보낸 돈은 돌아오지 않아요" · 한 번 더 확인.

### 11-4. 지급 건 상세(오른쪽 서랍)

- 머리: 크리에이터 · 정산월 · 상태 칩 · 금액.
- **담긴 정산 줄**: 상품 · 원래 달("○월분") · 지급액(§10-3 과 같은 줄).
- **지급 정보**: 지급일 · 그때 금액 · 그때 계좌(가림) · 자동 이체 / 수동 기록 · 메모 · 기록한 사람.
- **이체 시도**: 시도마다 시각 · 결과(성공 · 실패 종류 · 지급대행 응답 원문은 운영만) · 다음 시도 예정(재시도 대기면 "○월 ○일 오후 1시").
- **이력 타임라인**: 지급 건 생성 → 지급 보류(이유) → 세금계산서 확인 → 지급 대기 → 송금 시작 → 실패(종류) → 결과 조회 · 다시 보내기 → 지급 완료 · 운영 보류(메모 · 사람) → 해제 · 지급 완료 취소(사유) … 시각 · 사람(자동은 "자동").

## 12. 세금계산서 수취 확인

**무엇**: 사업자인 크리에이터가 MYR 에 세금계산서를 정발행하고 승인번호를 콘솔에 적는다. 운영이 홈택스에서 대조하고 확인해야 지급할 수 있다.

**정해진 값**(크리에이터 화면과 운영 화면이 같은 숫자를 보여 준다)
- 합계 = 정산금 − 제조금액 상계(보증금 환급은 넣지 않는다 · 이체만 같이).
- 공급가액 · 세액 = 합계를 나눈 값(세액 = 합계 ÷ 11 원 미만 버림 · 공급가액 = 나머지).
- 작성일자 = 정산월 말일 · 발행 기한 = 다음 달 10일. 기한이 지나도 지급 보류는 그대로이고 "기한 지남" 표시만 붙는다.
- 0원(전부 상계 · 보증금 환급만)이면 세금계산서가 필요 없다 — 목록에 나오지 않는다.

**세금계산서 상태**: 제출 전 · 확인 중 · 확인 완료 · 다시 제출 필요(+ 운영 사유). 크리에이터는 확인 전까지 승인번호를 고쳐 낼 수 있다.

- **크리에이터 콘솔 쪽(참고 · 만들어져 있음)**: 정산 상세 "지급까지 할 일" 카드 — ① 정산 정보 등록(등록하기 · 다시 입력 · 확인 중 · 완료) ② 세금계산서 발행(상태 칩 + 기한 지남 · 발행 기한 · "홈택스에 이대로 입력하세요" 표: 공급받는자 · 사업자등록번호 · 이메일 · 작성일자 · 공급가액 · 세액 · 합계 · 승인번호 입력 → 낸 승인번호 [수정] · 운영 요청 사유). 지급 정보에는 보류 사유 전부. 월별 정산 카드에 "세금계산서 발행 필요 / 기한 지남" 칩.
- **운영 `세금계산서` 목록**: 탭 **확인 중**(기본) · 다시 제출 필요 · 확인 완료 · 제출 전. 정산월 필터. 줄: 정산월 · 크리에이터 · 상호 · 사업자등록번호(홈택스 대조용 · 가림 + 보기) · 합계(공급가액 · 세액) · 작성일자 · 승인번호(복사 · 8-8-8) · 제출 시각 · 기한 지남 칩 · 지급 건 상태 · [홈택스 열기].
- **줄 동작**: **[수취 확인]** · **[다시 제출 요청](사유 필수 · 크리에이터에게 보인다)**.
    - 확인하면 지급 보류(세금계산서 확인 전) → 지급 대기 → **다음 오후 1시 자동 이체**(오후 1시 전에 확인하면 그날 · 버튼 옆에 "지금 확인하면 오늘 오후 1시 지급"). 사업자 정보 확인 전이면 그 이유로 계속 보류된다는 안내.
    - 목록 기본 정렬은 제출이 오래된 순 · 줄마다 기다린 시간("2일째").
    - 낸 뒤 합계가 바뀌었으면 확인이 거절된다 — "낸 합계 ○ · 지금 합계 ○ — 다시 발행을 요청하세요" + [다시 제출 요청].
    - 확인 완료도 지급 전이면 [다시 제출 요청]으로 되돌릴 수 있다(지급 완료 뒤에는 버튼 없음).
- **세금계산서 상세**: 위 값 + 이력(제출 · 고쳐 냄 · 확인 · 다시 제출 요청 사유 · 시각 · 사람).
- 지급 목록(§11-1)의 보류 이유 "세금계산서 확인 전" 줄에서 이 화면으로 바로 간다.
- 역발행이 가능해지면: 운영이 발행 → 크리에이터 승인 대기 → 승인 확인으로 흐름이 바뀐다(승인번호 입력 칸 대신 "발행 요청 · 승인 대기").

## 13. 아직 정해지지 않아 시안에서 열어 둘 것

정해진 것(2026-11-13):
- **교환 · 환불**: 운영은 처리 대기 요청을 기한과 관계없이 승인 · 반려할 수 있다(§8-2). 크리에이터 답변 기한(2일)은 표시만.
- **알림**: 심사 결과 · 지급 완료는 크리에이터 콘솔에서만 보인다(메일 · 알림 없음). 시안에 알림 설정 · 발송 화면을 그리지 않는다.

아직 열린 것:

- **지급대행 서비스**: 자동 이체는 결정(§11 · 2026-11-13). 시안은 선충전 잔액 · 결과 조회가 있는 서비스로 가정하고 그린다(§3 ② · §11). 어느 서비스로 보낼지에 따라 실패 이유 코드 → 네 종류 대응 · 잔액 조회 가능 여부 · [결과 조회]를 콘솔에서 할지 지급대행 화면에서 할지가 정해진다.
- **세금계산서 역발행**(§12): 지금은 정발행(크리에이터 발행 · 승인번호). 역발행이 가능해지면 MYR 발행 · 크리에이터 승인으로 바뀐다.
- **자주 쓰는 반려 의견 문구**(§4-2): 운영팀이 정하면 칩으로.
