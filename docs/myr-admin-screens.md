# MYR 운영 콘솔 — 화면 구성 (디자인 요청서)

2026-11-12 다시 씀. **Claude Design 에 올려 운영 콘솔 UI/UX 시안을 받기 위한 문서**다. 화면마다 무엇이 보이고, 무엇을 누를 수 있고, 상태에 따라 어떻게 달라지는지를 적었다.
만들 때 필요한 것(서버 함수 · 스크립트 · 결정)은 [docs/myr-admin-plan.md](myr-admin-plan.md) — 거기서 화면마다 "screens §번호"로 이 문서를 가리킨다.

---

## 0. 디자인 방향

- **서비스**: Make Your Recipe(MYR) — 크리에이터가 자기 레시피로 건강식품을 만들어 팔고, MYR 이 제조 · 판매 · 배송 · CS 를 대신하는 샵.
- **이 콘솔을 쓰는 사람**: MYR 운영팀(몇 명). 매일 상품 심사 · 발송 · 교환/환불을 처리하고, 매월 1일 전후로 제조금액 입력 · 정산 확인 · 크리에이터 지급을 한다.
- **기기**: **PC 우선**(1280~1440px). 표 · 2열 비교 · 오른쪽 고정 패널이 많은 업무 화면. 모바일은 홈 · 목록 확인 정도만 깨지지 않게.
- **톤**: 크리에이터 콘솔 시안 "MYR Influencer Admin"(다크 배경 · 오렌지 포인트 · 둥근 카드 · 작은 상태 칩)과 같은 계열. 운영 화면이라 더 촘촘하게 — 표 한 줄 높이 · 숫자 정렬(오른쪽 · 고정폭 숫자) 우선.
- **글자**: 한국어 · 금액은 `₩74,100` · 날짜는 `11월 12일(목)` · 시각은 `오후 1시` · 기간은 "3일째".

## 1. 공통 구성

### 1-1. 메뉴

왼쪽 고정 사이드 메뉴(또는 상단 내비 — 시안에서 제안). 메뉴 옆에 처리할 건수 배지.

| 메뉴 | 화면 | 우선 |
|---|---|---|
| 홈 | §3 대시보드 | 1 |
| 상품 | §4 목록 · 신규 심사 · 수정 심사 · 상품 관리 | 1 |
| 크리에이터 | §5 초대 · 목록 · 상세 | 1 · 2 |
| 주문 | §6 목록 · 상세 · 송장 일괄 · 배송 완료 예외 | 2 |
| 문의 | §7 목록 · 스레드 | 2 |
| 교환 · 환불 | §8 목록 · 상세 | 2 |
| 공구 링크 | §9 목록 | 3 |
| 정산 | §10 제조 원장 · 월 정산 | 2 · 3 |
| 지급 | §11 지급 목록 · 지급 건 상세 | 2 |
| 세금계산서 | §12 수취 확인 | 2 |

### 1-2. 자주 나오는 모양

- **목록 화면**: 페이지 제목 + 요약 숫자 → 탭(상태별 · 건수) → 필터 줄(크리에이터 · 기간 · 검색) → 표 → 줄을 누르면 상세(페이지 또는 오른쪽 서랍).
- **상세 화면**: 왼쪽 본문(내용 · 표) + 오른쪽 고정 패널(상태 · 처리 버튼 · 이력).
- **상태 칩 색**(크리에이터 콘솔과 같은 규칙):
    - 민트 = 예정 · 대기(지급 대기 · 지급 예정)
    - 빨강 = 보류 · 요청 · 막힘(지급 보류 · 교환/환불 요청 · 제조금액 확인 중)
    - 주황 = 진행 · 주의(상환 중 · 심사 N일째)
    - 회색 = 끝남(지급 완료 · 판매 종료 · 환불 완료)
- **되돌릴 수 없는 동작은 한 번 더 확인**: 첫 클릭에 버튼 줄이 `[취소] [정말 ○○하기]` 로 바뀐다(브라우저 확인창 없이 · 크리에이터 콘솔 반려/승인과 같은 방식). 반려 · 판매 종료 · 지급 완료 기록 · 지급 완료 취소 · 회수 확인 · 강제 종료.
- **사유 · 메모 입력**: 반려 · 정정 · 무효 · 운영 보류 · 지급 완료 취소 · 강제 종료는 사유가 필수 — 작은 모달 또는 패널 안 입력칸 + 글자 수.
- **민감 정보는 가린 값**: 연락처 `010-****-5678` · 계좌 `국민 ****5678` · 사업자번호 `***-**-12345`. 옆에 `[보기]` → 원문을 잠깐 보여 주고 "열람 기록이 남아요" 안내.
- **서버가 거절할 때**: 버튼 아래(또는 토스트)에 이유 한 줄 + 고칠 값. 예: "적은 금액이 지급 건 금액과 달라요 — 지급 건 금액 ₩74,100", "이체한 날이 정산 계산일(12월 1일) 전이에요".
- **빈 상태**: 탭마다 한 줄 안내("지급할 차례인 지급 건이 없어요").
- **처리한 사람 · 시각**: 상태가 바뀐 곳에는 "운영 김○○ · 11월 12일 오후 3:20" 을 작게.

## 3. 홈 대시보드

**무엇**: 오늘 처리할 일을 숫자 카드로. 카드를 누르면 그 목록(필터가 걸린 채)으로 간다.

카드 묶음(묶음마다 제목 · 카드 2~5개 · 급한 카드는 빨강 테두리):

| 묶음 | 카드 |
|---|---|
| 상품 | 신규 심사 대기 N(가장 오래 "3일째") · 수정 심사 대기 N · 재고 0 판매 중(품절) N |
| 주문 · 배송 | 발송 대기 N · 배송 완료 기록 없는 출고 N(정산에 못 들어간다 — 월말에 빨강) |
| 문의 · 교환/환불 | 답변 없는 문의(24시간 넘음) N · 회수 대기 N · 재발송 대기 N · 환불 다시 필요 N · 크리에이터 답변 기한 넘김 N |
| 크리에이터 | 새 초대 요청 N · 사업자 · 정산 정보 확인 대기 N |
| 정산 | 다음 정산일(매월 1일 오후 1시 · D-N) · 제조금액 미입력 판매 중 상품 N · 보류된 정산 N |
| 지급 | 지급할 차례 N건 · 금액 합 · 지급 보류 N건(이유별: 사업자 정보 확인 전 · 운영 보류 · 세금계산서 확인 전) · **지급일이 지났는데 지급 완료 기록이 없는 지급 건 N**(빨강) · 세금계산서 확인 대기 N · 발행 기한(다음 달 10일) 지났는데 안 낸 크리에이터 N(빨강) |

## 4. 상품

### 4-1. 상품 목록

- **탭**: 신규 심사 · 수정 심사 · 판매 중 · 일시중지 · 반려 · 판매 종료(건수). 임시저장은 필터로만.
- **정렬**: 심사 탭은 오래 기다린 순, 나머지는 최근 수정순.
- **표 줄**: 사진 · 상품명 · 크리에이터(@핸들) · 카테고리 · 가격 · 상태 칩 · "심사 N일째" 또는 "N일 전 승인" · 재고(남은 수량 · 0 이면 "품절" 빨강) · 판매 중인데 수정 심사가 걸려 있으면 "수정 심사 중" 칩도 같이.
- **필터**: 크리에이터 · 카테고리 · 검색(상품명 · 코드).

### 4-2. 신규 심사 상세

- **왼쪽 — 샵 상세 미리보기**: 고객이 보는 상품 페이지와 같은 순서로 그린다 — 구매 패널(사진 · 이름 · 가격 · 옵션) → 레시피 노트 → 01 왜 만들었나요 → 02 성분 → 03 섭취법 → 04 제품 정보 → 05 FAQ. 비어 있는 선택 섹션은 "비어 있음(샵에서 숨김)" 회색 블록.
    - 섹션 블록마다 오른쪽 위 **[의견 달기]** — 누르면 오른쪽 패널 의견 목록에 그 섹션이 골라진 새 줄이 생긴다. 의견이 달린 섹션은 테두리 강조.
- **오른쪽 — 검수 패널(고정)**:
    - 크리에이터(이름 · 핸들 · 연락처 가림) · 제출 시각 · 이전 반려 이력(있으면 그때 의견 접어서).
    - **의견 목록**: 줄마다 [섹션 고르기(1 기본 정보 ~ 7 FAQ · 전체)] + 문장 입력 · 삭제. 최대 10개 · 줄당 300자.
    - **자주 쓰는 의견** 칩(누르면 문장이 채워짐): "효능 · 최상급 표현", "의약품 오인 표현", "함량 근거 필요", "사진 해상도" 등(문구는 운영팀이 정한다).
    - **[반려]** — 의견 1개 이상 필요 · 한 번 더 확인.
    - **[승인]** — 누르면 **재고 입력**을 받는다(필수 · 0 이면 "샵에서 품절로 보여요" 경고) → 한 번 더 확인.
- **크리에이터 쪽에서는**: 반려되면 "심사 결과" → "반려 내용 고치기"(의견 달린 섹션에 "수정 필요" 칩) — 디자인 참고용.

### 4-3. 수정 심사(판매 중 상품의 수정본)

- **머리**: "수정 심사" 칩 · 요청 시각 · 안내 "승인 전까지 샵은 지금 내용으로 판매 중이에요".
- **본문 — 2열 비교**: 왼쪽 "지금 샵" · 오른쪽 "수정본". **바뀐 섹션만 펼쳐 강조**(바뀐 글자 표시), 안 바뀐 섹션은 접힌 한 줄.
- **오른쪽 패널**: 4-2 와 같은 의견 목록(기본 대상 = 바뀐 섹션) · 이 상품의 지난 수정 이력(반려 · 반영 · 취소).
- **[반영 승인]** · **[반려]** — 둘 다 한 번 더 확인. 반영해도 판매 상태 · 재고 · 옵션은 그대로라는 안내.
- 그사이 판매 종료된 상품이면 이 화면에 오지 않는다 / 승인 때 "상품 상태가 바뀌었어요" 거절 안내.

### 4-4. 상품 관리(같은 상세 화면 · 판매 중 · 일시중지 · 반려 · 종료)

- **판매 중 · 일시중지**: 오른쪽 패널 버튼 — [일시중지] / [다시 판매] · **[재고 수정]**(숫자 입력 · 0 이면 품절 안내) · **[판매 종료]**(되돌릴 수 없음 · 한 번 더 확인 · 열린 수정본은 취소된다는 안내).
- **제조 원장 칸**(→ §10-1 요약): 제조금액 · 보증금 · 남은 제조금액 · 갚은 비율 막대 · [원장 열기].
- **반려**: 보낸 의견 목록(읽기). 크리에이터가 다시 요청하면 신규 심사로 돌아온다.
- **판매 종료**: 읽기 전용 · 주문 · 환불 이력 링크.

## 5. 크리에이터

### 5-1. 초대

- **[초대 보내기]** 패널: 이메일 · 보낸 사람 이름 → 보내면 초대 링크 + [링크 복사].
- **목록 탭**: 대기 · 가입 완료 · 만료 · 취소 · **요청됨**(만료된 링크에서 "새 초대 요청하기"를 누른 사람).
- **줄 동작**: [다시 보내기](이전 링크는 무효) · [취소].

### 5-2. 크리에이터 목록

- 표 줄: 이름 · 핸들 · 계정 연결 여부 · 상품 수(판매 중/전체) · **사업자 정보 상태 칩**(미입력 · 확인 대기 · 확인 완료 · 다시 입력 요청) · 활동 상태(활성 · 정지) · 가입일.
- 필터: 사업자 정보 상태 · 활동 상태 · 검색.

### 5-3. 크리에이터 상세

탭 또는 세로 구획:

- **기본**: 이름 · 핸들 · 연락처(가림 + 보기) · 가입일 · **[정지] / [복구]**(정지하면 크리에이터 콘솔이 정지 화면 · 새 상품 저장 불가 — 한 번 더 확인) · **[계정 연결]**(로그인 계정이 없는 크리에이터).
- **사업자 · 정산 정보**: 상호 · 사업자등록번호(가림 + 보기) · 대표자 · 세금계산서 이메일 · 정산 계좌(가림 + 보기) · 제출 시각.
    - 상태가 "확인 대기"면 **[확인 완료]** · **[다시 입력 요청](사유 필수)**.
    - 그사이 크리에이터가 정보를 바꿨으면 "정보가 바뀌었어요 — 새 값으로 다시 확인해 주세요" + 새 값으로 다시 그림.
    - 확인 · 요청 뒤 "이 크리에이터의 지급 건 N건이 지급 대기/지급 보류로 바뀌었어요" 결과 한 줄(운영 보류 · 지급 완료 건은 그대로).
- **상품**: 이 크리에이터 상품 목록(§4-1 표 축소판).
- **활동**: 문의 응답률 · 최근 주문.
- **정산 요약**: 상품별 남은 제조금액 · 갚은 비율 · 보증금 상태 · 최근 정산 회차.
- **지급 이력**: 회차(정산월)별 줄 — 금액 · 상태 칩(지급 대기 · 지급 보류 + 이유 · 지급 완료 · 지급 없음) · 이체한 날 · 계좌(가림) · 운영 메모 · 줄을 열면 기록/취소 이력.

## 6. 주문 · 배송

### 6-1. 주문 목록

- 탭: 결제 완료 · 입금 대기 · 발송(배송 중) · 배송 완료 · 환불.
- 필터: 기간 · 크리에이터 · 주문번호 검색.
- 표 줄: 주문번호 · 결제일 · 주문자(가림) · 상품(첫 상품 외 N) · 크리에이터 · 금액 · 상태 칩 · 송장.

### 6-2. 주문 상세

- **주문 줄 표**: 상품 · 옵션 · 크리에이터 · 수량 · 금액 · 줄 상태 · 환불 이력(사진 · 상세).
- **수취인 · 결제**: 수취인(가림 + 보기 · 열람 기록) · 결제 수단 · 가상계좌.
- **송장**: 택배사 · 운송장 입력 · [송장 저장] → 고객에게 배송 시작 메일 · 이미 있으면 [정정].
- **예외 환불**: 사유 필수 · 크리에이터에게 알림 · 진행 중인 교환/환불이 있으면 경고 띠.

### 6-3. 송장 일괄 입력

- CSV 끌어다 놓기(`주문번호,택배사,운송장`) → **미리보기 표**(줄마다 정상 · 오류 이유) → [N건 저장] → 결과(성공 N · 실패 N + 실패 줄 내려받기).

### 6-4. 배송 완료 예외

**무엇**: 배송 중으로 오래(기본 5일) 남은 출고 줄. 배송 완료가 찍혀야 정산에 들어가므로 운영이 택배 조회로 확인하고 직접 찍는다.

- 표 줄: 주문번호 · 크리에이터 · 상품 · 택배사 · 운송장(**택배 조회 링크**) · 발송 후 며칠 · 이벗 등록 여부.
- 줄 동작: **[배송 완료]** → 실제 배송일 입력(기본 오늘) → 그 주문의 배송 중 줄 전부가 완료.
- 머리 경고: 월말(정산일 전)에 이 목록이 비어 있지 않으면 빨강 띠 "정산 전에 확인해 주세요".

## 7. 문의

- **목록**: 상태(답변 대기 · 답변 완료 · 종료) · 크리에이터 · "24시간 넘은 미답변" 필터 · 줄(문의번호 · 고객(가림) · 상품 · 첫 질문 · 경과 시간).
- **스레드**: 메신저 모양(고객 · 크리에이터 말풍선) · **대행 답변** 입력칸("고객에게는 크리에이터 이름으로 보여요" 안내) · [종료].

## 8. 교환 · 환불

### 8-1. 요청 목록

- 탭: **회수 대기** · **재발송 대기** · **환불할 차례(다시 필요)** · 처리 대기(크리에이터 답변 전) · 완료 · 반려 · 전체.
- 표 줄: 요청번호 · 주문번호 · 크리에이터 · 상품 × 수량 · 종류/사유 · 지금 단계 칩 · 접수 · 승인 시각 · 크리에이터 답변 기한(2일) 넘은 처리 대기는 빨강.

### 8-2. 요청 상세

- **왼쪽**: 고객 사진(크게 보기) · 상세 내용 · 크리에이터 메시지 · "주문 · 배송" 칸(요청 상품 · 함께 주문한 상품 · 줄 상태 — 크리에이터 콘솔과 같은 표) · 처리 타임라인(접수 → 승인 → 회수 → 환불/재발송).
- **오른쪽 패널(단계별 버튼)**:
    - 회수 대기 → **[회수 확인]**(한 번 더 확인 · 누르면 바로 환불이 나간다는 안내)
    - 재발송 대기 → **[재발송 송장 입력]**(택배사 · 송장 → 고객 메일)
    - 환불할 차례 → **[환불 다시]**
    - 처리 대기(크리에이터 미답변) → 운영 대행 승인 · 반려(미정 — §13)

## 9. 공구 링크

- 탭: 진행 중 · 예정 · 종료.
- 표 줄: 크리에이터 · 상품 · 공구가(기본가 대비 할인율 %) · 기간 · 링크 코드(복사) · 링크로 팔린 수량 · 매출.
- 줄 동작: **[강제 종료]**(잘못된 가격 · 기간일 때 · 사유 필수 · 한 번 더 확인).

## 10. 정산

정산은 매월 1일 오후 1시에 자동으로 계산 · 확정된다(화면에 [확정] 버튼 없음). 판매가의 60% 가 정산금, 크리에이터가 갚을 **제조금액**을 상품별로 먼저 빼고(상계), 다 갚으면 **보증금**(제조금액의 25%)을 돌려준다. 제조금액이 아직 입력되지 않은 상품은 **보류**된다.

### 10-1. 제조 원장

- **맨 위 — 입력 대기**(빨강 카드 두 묶음):
    1. **보류된 정산** — 상품 · 크리에이터 · 보류된 달 · 정산금 합계 · [제조금액 입력] → [보류 확정]. 확정 버튼 옆 안내: "다음 정산(○월 1일)에서 지급돼요".
    2. **판매 중인데 원장이 없는 상품** — "다음 정산에서 보류될 후보 · 매월 1일 전에 채워 주세요".
- **상품별 원장**(목록 → 상품 열기):
    - 요약: 제조금액 합 · 상계한 금액 · **남은 제조금액** · 갚은 비율 막대 · 보증금(입금 확인 · 입금 전 · 환급 완료).
    - **차수 표**: 차수 · 제조금액 · 보증금(25%) · 보증금 입금 확인일 · 환급 여부 · 메모 · 입력자 · 무효면 줄 긋기 + 사유.
    - 버튼: **[제조 차수 추가]**(재생산도 같은 버튼 · 0원 = "제조금액 없음") · **[보증금 입금 확인]**(날짜) · 줄마다 **[금액 정정]**(올바른 금액 · 사유) · **[무효]**(사유).
    - 정정 · 무효 결과 안내: "이미 상계한 ₩60,000 보다 작아 정정할 수 없어요 — 크리에이터에게 ₩60,000 을 따로 지급해야 해요" · "보증금 차액 ₩5,000 — 따로 돌려주거나 받아 주세요".
- 목록 필터: 남은 제조금액 있음 · 다 갚음 · 보증금 미입금 · 원장 없음.

### 10-2. 월 정산 — 회차 목록

- 표 줄: 정산월 · 계산 시각 · 누가(자동 · 운영) · 상품 수 · 확정/보류 수 · 정산금 합 · 상계 합 · 보증금 환급 합 · **지급 합계** · 지급 진행(지급 완료 N / 지급 건 N · 보류 N 막대).
- 머리 버튼: [회차 수동 실행](자동 실행이 실패했을 때만 · 끝난 달만).
- 경고 띠: 배송 완료 기록 없는 출고 · 원장 없는 판매 상품 · 사업자 정보 확인 전 크리에이터.

### 10-3. 월 정산 — 회차 상세

- **크리에이터별 묶음**(접고 펼치기). 묶음 머리줄 = **그 회차 지급 건**: 금액 · 상태 칩(지급 대기 · 지급 보류 + 이유 · 지급 완료 · 지급 없음) · 지급 가능 여부 · 이체한 날 · [지급 건 열기](→ §11).
- **상품 줄 표**: 상태(확정 · 보류) · 판매 · 정산 뒤 환불 · 이월 · 정산금(60%) · 남은 제조금액(전) · 상계 · 남은 제조금액(후) · 보증금 환급 · 지급액.
    - 줄 표시: "○월분 · 보류 해제"(지난 달 보류가 이 회차에 풀린 줄) · "○월 정산에서 지급"(이 달 줄인데 다른 회차에서 나간 줄 — 흐리게) · "다음 정산에서 지급".
    - 그래서 크리에이터 지급 건 금액과 줄 지급액 합이 다를 수 있다 — 머리줄에 작은 설명.
- **줄 펼쳐 보기**: 주문번호 · 고객(가림) · 배송 완료일 · 단가(공구 표시) · 수량 · 금액 · 판매/정산 뒤 환불 구분.

## 11. 지급

**무엇**: 매월 1일 정산 뒤 크리에이터에게 돈을 보내고 기록하는 곳. 크리에이터마다 회차당 **지급 건** 1건. 지금은 운영이 은행에서 직접 이체하고 여기서 "지급 완료"를 기록한다(자동 송금 방식은 미정 — §13). 기록하면 크리에이터 콘솔 정산 탭에 "지급 완료"와 이체한 날이 뜬다.

지급 건 상태: **지급 대기**(보낼 수 있음) · **지급 보류**(이유: 사업자 · 정산 정보 확인 전 / 운영팀 확인 중 / 세금계산서 확인 전) · **지급 완료** · **지급 없음**(0원 — 정산금이 전부 제조금액 상계).

### 11-1. 지급 목록

- **머리**: 정산월 고르기 · 요약(지급할 차례 N건 · ₩합계 / 보류 N건 / 완료 N건) · **[이체용 내려받기]**(지급할 차례 전체 · 계좌 원문이 들어가니 "열람 기록이 남아요").
- **탭**: **지급할 차례** · 지급 보류(이유별 하위 필터) · 지급 완료 · 지급 없음 · 전체.
- **표 줄**: 체크박스 · 크리에이터(이름 · @핸들) · 금액 · 담긴 줄 수("지난 달 보류분 포함" 표시) · 상태 칩 · 보류 이유 · 계좌(가림 + 보기) · 이체한 날 · 메모 · 줄 끝 버튼.
- **줄 끝 버튼**(상태별):
    - 지급 대기 → [지급 완료 기록] · [운영 보류]
    - 지급 보류(운영 보류) → [보류 해제]
    - 지급 보류(사업자 정보 · 세금계산서) → 버튼 없음 · "정보가 확인되면 자동으로 지급 대기가 돼요" + [크리에이터 열기]
    - 지급 완료 → [지급 완료 취소]
    - 지급 없음 → 없음
- **여러 줄 선택** → 아래 고정 바 "N건 선택 · ₩합계 · [지급 완료 기록]".

### 11-2. 지급 완료 기록(모달)

- 내용: 크리에이터 · 금액(지급 건 금액) · 받는 계좌(가림).
- 입력: **이체한 날**(기본 오늘 · 미래 날짜 막기) · **보낸 금액 확인**(금액을 다시 입력 — 틀리면 막힘) · 메모(선택).
- 버튼: [취소] [기록하기] → 한 번 더 확인 "정말 지급 완료로 기록할까요? 크리에이터 화면에 바로 보여요".
- 여러 건이면: 건별 금액 목록 + 합계 확인 + 같은 이체일 → 결과 화면(성공 N · 실패 N + 실패 이유 줄별).
- 거절 안내 예시: "지급 보류 중이에요(사업자 · 정산 정보 확인 전)" · "이미 11월 11일에 지급 완료로 기록됐어요" · "보낸 금액이 지급 건 금액(₩74,100)과 달라요" · "이체한 날이 정산 계산일(12월 1일) 전이에요" · "오늘 이후 날짜는 기록할 수 없어요".

### 11-3. 운영 보류 · 보류 해제 · 지급 완료 취소(작은 모달)

- **운영 보류**: 메모 필수("계좌 확인 요청" 등) · 안내 "크리에이터에게는 '운영팀 확인 중'으로만 보여요 · 메모는 운영만 봐요".
- **보류 해제**: 안내 "해제하면 지금 상태로 다시 정해져요(사업자 정보 확인 전이면 다시 지급 보류)".
- **지급 완료 취소**: 사유 필수 · 빨강 안내 "기록만 되돌려요. 이미 보낸 돈은 돌아오지 않아요" · 한 번 더 확인.

### 11-4. 지급 건 상세(오른쪽 서랍)

- 머리: 크리에이터 · 정산월 · 상태 칩 · 금액.
- **담긴 정산 줄**: 상품 · 원래 달("○월분") · 지급액(§10-3 과 같은 줄).
- **지급 정보**: 이체한 날 · 그때 금액 · 그때 계좌(가림) · 메모 · 기록한 사람.
- **이력 타임라인**: 지급 건 생성 → 지급 보류(이유) → 운영 보류(메모 · 사람) → 해제 → 지급 완료 기록 → 지급 완료 취소(사유) … 시각 · 사람.

## 12. 세금계산서 수취 확인

**무엇**: 사업자인 크리에이터가 MYR 에 세금계산서를 정발행하고 승인번호를 콘솔에 적는다. 운영이 홈택스에서 대조하고 확인해야 지급할 수 있다.

**정해진 값**(크리에이터 화면과 운영 화면이 같은 숫자를 보여 준다)
- 합계 = 정산금 − 제조금액 상계(보증금 환급은 넣지 않는다 · 이체만 같이).
- 공급가액 · 세액 = 합계를 나눈 값(세액 = 합계 ÷ 11 원 미만 버림 · 공급가액 = 나머지).
- 작성일자 = 정산월 말일 · 발행 기한 = 다음 달 10일. 기한이 지나도 지급 보류는 그대로이고 "기한 지남" 표시만 붙는다.
- 0원(전부 상계 · 보증금 환급만)이면 세금계산서가 필요 없다 — 목록에 나오지 않는다.

**세금계산서 상태**: 제출 전 · 확인 중 · 확인 완료 · 다시 제출 필요(+ 운영 사유). 크리에이터는 확인 전까지 승인번호를 고쳐 낼 수 있다.

- **크리에이터 콘솔 쪽(참고 · 만들어져 있음)**: 정산 상세 "지급 정보" 아래 "세금계산서" 칸 — 상태 칩(+ 기한 지남) · 공급가액 · 세액 · 합계 · 작성일자 · 발행 기한 · 공급받는자(MYR 상호 · 사업자등록번호) · 승인번호 입력 · 운영 요청 사유. 월별 정산 카드에 "세금계산서 발행 필요 / 기한 지남" 칩.
- **운영 `세금계산서` 목록**: 탭 **확인 중**(기본) · 다시 제출 필요 · 확인 완료 · 제출 전. 정산월 필터. 줄: 정산월 · 크리에이터 · 상호 · 사업자등록번호(홈택스 대조용 · 가림 + 보기) · 합계(공급가액 · 세액) · 작성일자 · 승인번호(복사 · 8-8-8) · 제출 시각 · 기한 지남 칩 · 지급 건 상태 · [홈택스 열기].
- **줄 동작**: **[수취 확인]** · **[다시 제출 요청](사유 필수 · 크리에이터에게 보인다)**.
    - 확인하면 지급 보류(세금계산서 확인 전) → 지급 대기. 사업자 정보 확인 전이면 그 이유로 계속 보류된다는 안내.
    - 낸 뒤 합계가 바뀌었으면 확인이 거절된다 — "낸 합계 ○ · 지금 합계 ○ — 다시 발행을 요청하세요" + [다시 제출 요청].
    - 확인 완료도 지급 전이면 [다시 제출 요청]으로 되돌릴 수 있다(지급 완료 뒤에는 버튼 없음).
- **세금계산서 상세**: 위 값 + 이력(제출 · 고쳐 냄 · 확인 · 다시 제출 요청 사유 · 시각 · 사람).
- 지급 목록(§11-1)의 보류 이유 "세금계산서 확인 전" 줄에서 이 화면으로 바로 간다.
- 역발행이 가능해지면: 운영이 발행 → 크리에이터 승인 대기 → 승인 확인으로 흐름이 바뀐다(승인번호 입력 칸 대신 "발행 요청 · 승인 대기").

## 13. 아직 정해지지 않아 시안에서 열어 둘 것

- **송금 방식**: 지금은 직접 이체 + 기록. 토스 지급대행이면 [지급 완료 기록] 대신 [송금 요청] · 자동 결과가 붙고, 이체 파일이면 [이체용 내려받기] 양식이 은행 일괄 이체 형식이 된다.
- **세금계산서 역발행**(§12): 지금은 정발행(크리에이터 발행 · 승인번호). 역발행이 가능해지면 MYR 발행 · 크리에이터 승인으로 바뀐다.
- **교환 · 환불 대행 처리**: 크리에이터가 2일 안에 답하지 않으면 운영이 대신 승인 · 반려할지(§8-2 버튼 자리만 비워 둔다).
- **알림**: 심사 결과 · 지급 완료를 크리에이터에게 메일로 알릴지(지금은 콘솔에서만 보인다).
- **자주 쓰는 반려 의견 문구**(§4-2): 운영팀이 정하면 칩으로.
