## 0. 디자인 방향

- **서비스**: Make Your Recipe(MYR) — 크리에이터가 자기 레시피로 건강식품을 만들어 팔고, MYR 이 제조 · 판매 · 배송 · CS 를 대신하는 샵.
- **이 콘솔을 쓰는 사람**: MYR 운영팀(몇 명). 매일 상품 심사 · 발송 · 교환/환불을 처리하고, 매월 1일 전후로 제조금액 입력 · 정산 확인을 한다. **크리에이터 지급은 자동 이체**(영업일 오후 1시 · §11) — 운영은 세금계산서 수취 확인과 이체 실패 · 보류 같은 예외만 처리한다.
- **기기**: **PC 우선**(1280~1440px). 표 · 2열 비교 · 오른쪽 고정 패널이 많은 업무 화면. 모바일은 홈 · 목록 확인 정도만 깨지지 않게.
- **톤**: 크리에이터 콘솔 시안 "MYR Influencer Admin"(다크 배경 · 오렌지 포인트 · 둥근 카드 · 작은 상태 칩)과 같은 계열. 운영 화면이라 더 촘촘하게 — 표 한 줄 높이 · 숫자 정렬(오른쪽 · 고정폭 숫자) 우선.
- **글자**: 한국어 · 금액은 `₩74,100` · 날짜는 `11월 12일(목)` · 시각은 `오후 1시` · 기간은 "3일째".

## 1. 공통 구성

### 1-1. 메뉴

**PC 는 상단 메뉴 72px**(시안 "MYR Admin PC" · 2026-11-24) — 왼쪽 로고 + ADMIN · 메뉴 홈 · 상품 · 크리에이터 · 주문 · CS 관리 · 정산 · 지급 · 세금계산서(공구 링크는 2026-11-27 상품 메뉴 안 하위 화면으로 옮김 · §9)(고른 메뉴는 흰 글자 + 주황 밑줄) · 오른쪽 **파트너팀 톡 아이콘**(메뉴가 아니라 버튼 · 답할 차례 수 주황 배지) · **내 계정 버튼**(이름 · MYR 운영팀 · 로그아웃 메뉴). 메뉴 옆에 처리할 건수 배지(회색 · 고른 메뉴는 주황). 모바일은 머리(로고 + ADMIN · 오른쪽 같은 파트너팀 톡 · 내 계정 버튼 · 본문과 같이 스크롤 · 시안 "MYR Admin") + **하단 탭**(본문 위에 떠 있는 5칸 — 홈 · 상품 · 주문 · CS 관리 · 전체 · 처리할 건수 주황 배지) + **전체 메뉴**("전체"를 누르면 화면을 덮는 목록 — PC 상단 메뉴와 같은 순서 · 이름 · 배지, 파트너팀 톡은 머리 아이콘이라 빠진다). ~~머리에 화면 제목이 없으므로 화면 제목은 본문 맨 위에 보인다.~~ → 목록 화면은 큰 제목 없이 요약 · 탭부터 시작한다(2026-11-26 · §1-2).

### 1-2. 자주 나오는 모양

- **목록 화면**: ~~페이지 제목~~ + 요약 숫자 → 탭(상태별 · 건수) → 필터 줄(크리에이터 · 기간 · 검색) → 표 → 줄을 누르면 상세(페이지 또는 오른쪽 서랍). **큰 제목은 보이지 않는다(2026-11-26)** — 상단 메뉴 · 하단 탭에 이름이 있으므로 상품 · 크리에이터 · 공구 링크 · 지급 · 세금계산서 · 파트너팀 톡도 주문 · CS 처럼 요약 줄 · 버튼(또는 탭)부터 시작한다(제목은 화면 읽기용으로만). 상품은 탭 오른쪽에 요약(심사 대기 · 판매 중), 크리에이터는 탭 오른쪽에 [초대 보내기]. 상세 화면의 이름 제목(상품명 · 크리에이터 이름 등)은 그대로.
- **상세 화면**: 왼쪽 본문(내용 · 표) + 오른쪽 고정 패널(상태 · 처리 버튼 · 이력).
- **상태 칩 색**(크리에이터 콘솔과 같은 규칙):
    - 민트 = 예정 · 대기 · 진행(지급 대기 · 송금 중)
    - 빨강 = 보류 · 요청 · 막힘(지급 보류 · 결과 확인 필요 · 운영 조치 필요 · 계좌 확인 필요 · 교환/환불 요청 · 제조금액 확인 중)
    - 주황 = 진행 · 주의(재시도 대기 · 상환 중 · 심사 N일째)
    - 회색 = 끝남(지급 완료 · 판매 종료 · 환불 완료)
- **되돌릴 수 없는 동작은 한 번 더 확인**: 첫 클릭에 버튼 줄이 `[취소] [정말 ○○하기]` 로 바뀐다(브라우저 확인창 없이 · 크리에이터 콘솔 반려/승인과 같은 방식). 반려 · 판매 종료 · 지급 완료 기록 · 지급 완료 취소 · 회수 확인. (공구 링크 강제 종료는 시안대로 확인 창 하나 — §9)
- **사유 · 메모 입력**: 반려 · 정정 · 무효 · 운영 보류 · 지급 완료 취소는 사유가 필수 — 작은 모달 또는 패널 안 입력칸 + 글자 수.
- **민감 정보는 가린 값**: 연락처 `010-****-5678` · 계좌 `국민 ****5678` · 사업자번호 `***-**-12345`. 옆에 `[보기]` → 원문을 잠깐 보여 주고 "열람 기록이 남아요" 안내.
- **서버가 거절할 때**: 버튼 아래(또는 토스트)에 이유 한 줄 + 고칠 값. 예: "적은 금액이 지급 건 금액과 달라요 — 지급 건 금액 ₩74,100", "이체한 날이 정산 계산일(12월 1일) 전이에요".
- **빈 상태**: 탭마다 한 줄 안내("실패한 지급 건이 없어요").
- **처리한 사람 · 시각**: 상태가 바뀐 곳에는 "운영 김○○ · 11월 12일 오후 3:20" 을 작게. 자동 처리는 "자동 · 11월 7일 오후 1:02".
- **글자 크기 · 대비**: 보조 글자(시각 · 빈 상태 · 표 열 제목 · placeholder)도 배경 대비 4.5:1 이상(흰 글자 투명도 최소 `.55`). 칩 · 배지는 12~13px. 모바일 버튼 터치 영역 44px 이상.

### 1-3. 상태 이름(용어집)

상태 하나에 이름 하나. 운영 콘솔과 크리에이터 콘솔은 같은 서버 상태를 다른 말로 보여 줄 수 있다 — 아래 표 밖의 이름(예: "지급할 차례" · "지급일 지남" · "결제 완료"를 발송 대기 뜻으로)은 쓰지 않는다.

| 서버 상태 | 운영 콘솔 | 크리에이터 콘솔(만들어져 있음 · 0111) |
|---|---|---|
| 지급 건 · 보낼 수 있음 | 지급 대기 | 지급 예정 |
| 지급 건 · 보류 | 지급 보류 + 이유 전부 | 지급 보류 |
| 이체 · 송금 중 | 송금 중 | 지급 중 |
| 이체 실패 · 잠깐 안 됨 | 재시도 대기 | 지급 지연 |
| 이체 실패 · 계좌 문제 | 계좌 확인 필요 | 지급 실패 |
| 이체 실패 · 이체 한도 | 운영 조치 필요 | 지급 확인 중 |
| 이체 실패 · 결과 불명 | 결과 확인 필요 | 지급 확인 중 |
| 토스 셀러 · 본인인증 전(`APPROVAL_REQUIRED` · `KYC_REQUIRED`) | 지급 보류(토스 본인인증 전) · 크리에이터 탭 · 칩 "토스 인증 대기" | (크리에이터 콘솔 문구는 본인인증 화면을 만들 때 정한다) |
| 지급 건 · 끝남 | 지급 완료 | 지급 완료 |
| 지급 건 · 0원 | 지급 없음 | 지급 없음 |
| 주문 줄 · 발송 전 | 발송 대기 | — |

- 크리에이터에게는 운영 쪽 실패 원인(이체 한도 · 결과 불명)을 보여 주지 않는다 — "운영팀이 지급을 확인하고 있어요".
- 보류와 이체 실패가 겹치면: 운영 콘솔은 **둘 다** 칩으로(보류 중에는 자동 재시도하지 않는다는 안내) · 크리에이터 콘솔은 "지급 보류"만.

## 3. 홈 대시보드

**무엇**: 돈이 얼마 남았는지 · 무엇이 막혔는지 · 오늘 무엇을 처리할지를 한 화면에. 숫자나 칩을 누르면 그 목록(필터가 걸린 채)으로 간다. **시안 "MYR Admin"(모바일) · "MYR Admin PC" 홈과 같다(2026-11-24).** 숫자 · 문구 · 색 구분은 서버 값 하나(콘솔 목 `server.home`)에서 온다.

**배치**: PC 는 위 4칸 그리드(① 히어로 2칸 · ② 카드 두 개) → 아래 2열(③ 처리할 일 1.6 : ④ 정산 일정 1). 모바일은 ① → ② 두 칸 → ③ → ④ 세로. 화면 제목은 없다(스크린 리더용 "홈"만).

**① 히어로 — 아직 지급하지 않은 금액**
- 제목 "10월분 · 아직 지급하지 않은 금액" + 큰 숫자(지급 합계 − 지급 완료 금액) · 오른쪽 [지급 보기](실패가 있으면 지급 실패 탭, 없으면 지급 보류 탭).
- 작은 숫자 셋: 지급 합계 · 지급 완료 N/N건 · **운영 확인 필요 N건**(결과 확인 필요 + 운영 조치 필요 · 있으면 주황).
- 아래 줄 **토스 지급 가능 잔액** ₩○ + "충분해요"(민트) 또는 "₩○ 모자라요"(주황 — 다음 실행에 보내야 할 금액(지급 가능 안에 든 것 + 모자라 넘어가는 것)보다 적을 때) · "들어올 예정 ₩○"(토스 정산 전 · 있을 때만) · [새로고침].
  - 모자란 건은 실패가 아니다 — 지급 대기 그대로 토스 정산 뒤 다음 영업일에 보낸다(§11 "잔액"). 그래서 모자랄 때는 잔액 바로 아래에 "모자란 N건은 다음 영업일에 자동으로 보내요" 한 줄(놀라지 않게). PC 는 같은 줄에 " · 들어올 예정 ₩○" · 모바일은 "들어올 예정"을 보이지 않는다(시안).

**② 카드 두 개**(PC 는 히어로 옆 세로형 두 칸 · 모바일은 위아래로 쌓은 가로형 — 아이콘 · 글 · 오른쪽 큰 숫자)
- **세금계산서 확인 대기** N(주황 카드 · **0건이면 회색 카드** — 급해 보이지 않게) — 있으면 민트 칩 "지금 확인하면 오늘 오후 1시 지급"(오후 1시가 지났으면 "다음 영업일") · 없으면 "확인할 세금계산서가 없어요". → 세금계산서 확인 중 탭.
- **심사 대기 상품** N — "신규 N · 수정 N". → 상품.

**③ 처리할 일**(메뉴 8줄 · 순서 고정 · 정렬하지 않는다 · 2026-11-26 제목 "오늘 처리할 일" → "처리할 일")
- 머리 오른쪽 "급한 일 N가지"(빨강 칩 수 · 없으면 "급한 일이 없어요" 회색).
- 줄 = 메뉴 아이콘 타일(칩 중 가장 급한 색: 빨강 · 주황 · 회색) · 메뉴 이름 · 칩들 · ›. 줄을 누르면 그 메뉴, 칩을 누르면 그 필터. 칩이 없으면 "처리할 일이 없어요".
- 칩 색: **빨강**(급함) · **주황 숫자**(처리할 일) · **회색**(기다리기만 하면 됨).

| 줄 | 칩 |

    - 사업자등록번호가 바뀌면 토스에서는 수정이 안 돼 셀러를 지우고 다시 등록한다(다시 본인인증) — "사업자번호가 바뀌어 토스 등록을 다시 해요" 안내.
    - **재인증(2026-11-20 · 0124)**: 확인 대기 줄에 **"재인증 필요" 칩**(사업자번호 · 대표자 변경 · 법인 제외 — 운영 목록 응답 `reauth` · `myr_toss_reauth_pending`) · 상세에 "확인하면 토스에 다시 등록되고, 크리에이터가 대표자 휴대폰으로 본인인증을 마쳐야 확인 완료예요". ### 11-1. 지급 목록

- **머리**: 정산월 고르기 · 요약(지급 합계 · 자동 지급 완료 N/N건 · 실패 N · 보류 N) · **다음 자동 이체(영업일 오후 1시) N건 · ₩합계**(모자라 넘어가는 건이 있으면 "N건은 토스 정산 뒤 다음 영업일" 주황) · **토스 지급 가능 ₩○ · 정산 전 ₩○**(항상 · 새로고침 · 빨강 없음) · 마지막 실행 결과. 값은 §3 ②와 같다.
- **탭**: **지급 실패**(실패가 있으면 기본 · 종류별 하위 필터) · 지급 보류(이유별 하위 필터 — 이유가 하나라도 걸린 건이 나온다) · 지급 대기 · 송금 중 · 지급 완료 · 지급 없음 · 전체.
- **표**(한 줄 40~48px · 열 제목 · 정렬): 체크박스 · 크리에이터(이름 · @핸들) · 금액 · 담긴 줄 수("지난 달 보류분 포함" 표시) · 상태 칩 · 실패 종류 · 보류 이유 · 시도 횟수 · 마지막 시도 시각 · 계좌(가림 + 보기) · 지급일 · 메모 · 줄 끝 버튼.
    - 보류 이유는 걸린 것 **전부**를 보여 준다(예: "운영팀 확인 중 · 사업자 · 정산 정보 확인 전 · 세금계산서 확인 전" · "토스 본인인증 전"). 운영 보류가 있으면 맨 앞, 그다음 사업자 정보 → 토스 본인인증 → 세금계산서 순.
    - 보류와 실패가 겹치면 칩 둘 다 + "보류 중이라 자동으로 다시 보내지 않아요".
- **줄 끝 버튼**(상태별):
    - 지급 실패 → 위 표의 버튼
    - 지급 대기 → [운영 보류]("오늘 오후 1시 전에 걸면 이번 이체에서 빠져요")
    - 송금 중 → 없음("은행 처리 중")
    - 지급 보류(운영 보류) → [보류 해제] · 다른 이유도 걸려 있으면 "해제해도 ○○ 때문에 계속 보류돼요" 안내(해제하면 남은 이유로 자동 보류)
    - 지급 보류(사업자 정보 · 세금계산서) → 버튼 없음 · "정보가 확인되면 자동으로 지급 대기가 돼요" + [크리에이터 열기] · [세금계산서 열기]
    - 지급 완료 → [지급 완료 취소](수동 기록만 · 자동 이체 완료 건은 취소 대신 운영 메모)
    - 지급 없음 → 없음
- **여러 줄 선택** → 아래 고정 바 "N건 선택 · ₩합계 · [운영 보류] · [다시 보내기](운영 조치 필요만)".
- **예외 처리**(머리 오른쪽 "더보기" 안 · 평소에는 숨김): [지급 완료 기록](결과 확인 필요를 토스 대시보드에서 "실제로 나갔다"고 확인했을 때 · 0127) · [다시 보내기](운영 조치 필요 · 결과 확인 필요를 토스에서 "실패"로 확인했을 때 — 다음 자동 이체에 · 메모 필수). 이체용 내려받기는 없다(0127 — 수동 이체를 걷어냈다).

### 11-2. 지급 완료 기록(모달 · 예외 처리)

자동 이체 밖에서 직접 보냈을 때만 쓴다(지급대행 장애 · 결과 확인 필요를 직접 이체로 정리할 때).


- 내용: 크리에이터 · 금액(지급 건 금액) · 받는 계좌(가림).
- 입력: **이체한 날**(기본 오늘 · 미래 날짜 막기) · **보낸 금액 확인**(금액을 다시 입력 — 틀리면 막힘) · 메모(선택).
- 버튼: [취소] [기록하기] → 한 번 더 확인 "정말 지급 완료로 기록할까요? 크리에이터 화면에 바로 보여요".
- 여러 건이면: 건별 금액 목록 + 합계 확인 + 같은 이체일 → 결과 화면(성공 N · 실패 N + 실패 이유 줄별).
- 거절 안내 예시: "지급 보류 중이에요(사업자 · 정산 정보 확인 전)" · "이미 11월 11일에 지급 완료로 기록됐어요" · "보낸 금액이 지급 건 금액(₩74,100)과 달라요" · "이체한 날이 정산 계산일(12월 1일) 전이에요" · "오늘 이후 날짜는 기록할 수 없어요".

### 11-3. 운영 보류 · 보류 해제 · 지급 완료 취소(작은 모달)

- **운영 보류**: 메모 필수("계좌 확인 요청" 등) · 안내 "크리에이터에게는 '운영팀 확인 중'으로만 보여요 · 메모는 운영만 봐요".
- **보류 해제**: 안내 "해제하면 지금 상태로 다시 정해져요(사업자 정보 확인 전이면 다시 지급 보류)".
- **지급 완료 취소**: 사유 필수 · 빨강 안내 "기록만 되돌려요. 이미 보낸 돈은 돌아오지 않아요" · 한 번 더 확인.

### 11-4. 지급 건 상세(오른쪽 서랍)

- 머리: 크리에이터 · 정산월 · 상태 칩 · 금액.
- **담긴 정산 줄**: 상품 · 원래 달("○월분") · 지급액(§10-3 과 같은 줄).
- **지급 정보**: 지급일 · 그때 금액 · 그때 계좌(가림) · 자동 이체 / 수동 기록 · 메모 · 기록한 사람.
- **이체 시도**: 시도마다 시각 · 결과(성공 · 실패 종류 · 지급대행 응답 원문은 운영만) · 다음 시도 예정(재시도 대기면 "○월 ○일 오후 1시").
- **이력 타임라인**: 지급 건 생성 → 지급 보류(이유) → 세금계산서 확인 → 지급 대기 → 송금 시작 → 실패(종류) → 자동 확인 · 다시 보내기 → 지급 완료 · 운영 보류(메모 · 사람) → 해제 · 지급 완료 취소(사유) … 시각 · 사람(자동은 "자동").

## 12. 세금계산서 수취 확인

**무엇**: 사업자인 크리에이터가 MYR 에 세금계산서를 정발행하고 승인번호를 콘솔에 적는다. 운영이 홈택스에서 대조하고 확인해야 지급할 수 있다.

**정해진 값**(크리에이터 화면과 운영 화면이 같은 숫자를 보여 준다)
- 합계 = 정산금 − 제조금액 상계(보증금 환급은 넣지 않는다 · 이체만 같이).
- 공급가액 · 세액 = 합계를 나눈 값(세액 = 합계 ÷ 11 원 미만 버림 · 공급가액 = 나머지).
- 작성일자 = 정산월 말일 · 발행 기한 = 다음 달 10일. 기한이 지나도 지급 보류는 그대로이고 "기한 지남" 표시만 붙는다.
- 0원(전부 상계 · 보증금 환급만)이면 세금계산서가 필요 없다 — 목록에 나오지 않는다.

**세금계산서 상태**: 제출 전 · 확인 중 · 확인 완료 · 다시 제출 필요(+ 운영 사유). 크리에이터는 확인 전까지 승인번호를 고쳐 낼 수 있다.

- **크리에이터 콘솔 쪽(참고 · 만들어져 있음)**: 정산 상세 "지급까지 할 일" 카드 — ① 정산 정보 등록(등록하기 · 다시 입력 · 확인 중 · 완료) ② 세금계산서 발행(상태 칩 + 기한 지남 · 발행 기한 · "홈택스에 이대로 입력하세요" 표: 공급받는자 · 사업자등록번호 · 이메일 · 작성일자 · 공급가액 · 세액 · 합계 · 승인번호 입력 → 낸 승인번호 [수정] · 운영 요청 사유). 지급 정보에는 보류 사유 전부. 월별 정산 카드에 "세금계산서 발행 필요 / 기한 지남" 칩.
- **운영 `세금계산서` 목록**: 탭 **확인 중**(기본) · 다시 제출 필요 · 확인 완료 · 제출 전. 정산월 필터. 줄: 정산월 · 크리에이터 · 상호 · 사업자등록번호(홈택스 대조용 · 가림 + 보기) · 합계(공급가액 · 세액) · 작성일자 · 승인번호(복사 · 8-8-8) · 제출 시각 · 기한 지남 칩 · 지급 건 상태 · [홈택스 열기].
- **줄 동작**: **[수취 확인]** · **[다시 제출 요청](사유 필수 · 크리에이터에게 보인다)**.
    - 확인하면 지급 보류(세금계산서 확인 전) → 지급 대기 → **다음 자동 이체(영업일 오후 1시)**(오후 1시 전에 확인하면 그날 · 버튼 옆에 "지금 확인하면 오늘 오후 1시 지급"). 사업자 정보 확인 전이면 그 이유로 계속 보류된다는 안내.
    - 목록 기본 정렬은 제출이 오래된 순 · 줄마다 기다린 시간("2일째").
    - 낸 뒤 합계가 바뀌었으면 확인이 거절된다 — "낸 합계 ○ · 지금 합계 ○ — 다시 발행을 요청하세요" + [다시 제출 요청].
    - 확인 완료도 지급 전이면 [다시 제출 요청]으로 되돌릴 수 있다(지급 완료 뒤에는 버튼 없음).
- **세금계산서 상세**: 위 값 + 이력(제출 · 고쳐 냄 · 확인 · 다시 제출 요청 사유 · 시각 · 사람).
- 지급 목록(§11-1)의 보류 이유 "세금계산서 확인 전" 줄에서 이 화면으로 바로 간다.
- 역발행이 가능해지면: 운영이 발행 → 크리에이터 승인 대기 → 승인 확인으로 흐름이 바뀐다(승인번호 입력 칸 대신 "발행 요청 · 승인 대기").

## 13. 아직 정해지지 않아 시안에서 열어 둘 것

정해진 것(2026-11-13):
- **교환 · 환불**: 운영은 처리 대기 요청을 기한과 관계없이 승인 · 반려할 수 있다(§8-2). 크리에이터 답변 기한(2일)은 표시만.
- **알림**: 심사 결과 · 지급 완료는 크리에이터 콘솔에서만 보인다(메일 · 알림 없음). 시안에 알림 설정 · 발송 화면을 그리지 않는다.
- **지급대행**(2026-11-18): 토스페이먼츠 지급대행 v2 — 영업일 오후 1시 · 잔액은 판매 정산대금(지급 가능 안에서만 보냄) · 크리에이터마다 토스 셀러 등록 · 단건 조회 `GET /v2/payouts/{id}` 로 매시간 확인(§5-3 · §11).

아직 열린 것:

- **토스 지급대행 세부**(서비스는 2026-11-18 토스페이먼츠로 결정 · §11): 토스 실패 `error` 코드 → 네 종류(재시도 대기 · 계좌 확인 필요 · 운영 조치 필요 · 결과 확인 필요) 대응표 · 자동 확인 간격(1시간)과 운영에게 넘기는 시점(24시간) · 크리에이터 휴대폰 본인인증을 어디서 하게 할지(크리에이터 콘솔 · 토스 화면) · 이체 적요(7자 이하 · 기본 상점명) · 테스트 환경은 법인 셀러만 등록되고 `APPROVED` 까지 못 가서 개인 크리에이터 흐름은 라이브 키로만 끝까지 확인된다.

- **파트너팀 톡**(§7-2): 답할 차례가 몇 시간 지나면 빨강으로 바꿀지(기준 시간) · 크리에이터가 보냈을 때 운영에게 슬랙 알림을 보낼지 · 자주 쓰는 답장 문구.
